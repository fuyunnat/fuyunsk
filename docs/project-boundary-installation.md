# 所有写入边界的安装与验收


完整复制时包含 `references/project-write-boundary.md` 与 `scripts/project-path-check.js`，同步个性化短块的所有写入规则。安装技能不等于本机隔离生效；不得写死业务路径、自动扩展可写根、覆盖业务文件或将恢复事故混入安装。

先只读核实当前会话源目录、实际 sandbox、附加 writable_roots 和编辑/终端工具约束；不用终端默认配置冒充应用实际状态。只报告相关项，凭证不输出。当前工作区应精确到本次项目而非共同父开发目录；writable_roots 是附加范围，不会排除已可写的其他路径。需要收紧时先给精确方案并取得授权，不顺手改模型、API、MCP 或其他权限。

用已有 Node.js 运行 `project-path-check.js --help`；在获准的独立合成目录绑定项目甲，检查甲内新文件可通过、乙内文件被拒绝，验证乙的哨兵文件未变；再测试错误 workdir、同前缀兄弟目录、链接和已有新工程目标。没有 Node.js 不自动安装，说明预检程序未执行。

以上只是路径预检验证。宿主真实沙箱的负向写入测试必须另获批准并只用合成项目，不在实际商城目录做试写；必须使用与真实任务相同的启动权限，覆盖编辑和终端入口。失败立即停止，不请求扩大权限再测。缺少这一步，报告“真实沙箱隔离未验证”；不把文档断言、脚本通过或一次路径检查冒充跨项目强隔离。发生过误覆盖的业务目标保持暂停，先确认隔离及另行授权的现场备份/恢复方案。
