# 个性化自动调用指令

默认安装同时配置这里的短调度规则和本机技能，不再把个性化接入当成可省略步骤。用户另行明确要求“只安装技能，不修改个性化”时，保留该限制并说明未完成接入。

桌面端“设置 → 个性化 → Codex 说明”对应个人 `AGENTS.md`，不是另一份需要重复安装的技能。AI 应按[安装教程](ai-installation.md)核实实际文件、备份并合并，不能用本文件全文覆盖用户已有内容。

## 要合并的短规则

下面代码块与仓库根目录的 [global-AGENTS.example.md](../global-AGENTS.example.md) 是同一模板，不是两套规则。安装时将路径占位符替换为本机实际存在的 `SKILL.md` 绝对路径；升级时只更新标记块，不重复追加。

```markdown
<!-- production-engineering:auto:start -->
# 工程技能自动调用

技能入口：`<已核实的SKILL.md绝对路径>`

- 默认中文沟通；工程提交、评审和交付说明按原规范使用中文，命令、路径和技术标识保留原样。
- 真实项目的实现、修复、调试、前端界面、代码与安全审查、Git、数据库和部署任务，主动使用 `$production-engineering`，不要求我每次手写技能名。
- 使用时读取技能入口并批量读取适用原文；用户已给源码先读相关实现，锁定改变项与保留项。源码可查的不反问；关键歧义查证后再问，暂停相关修改。不读不称已读，不删规则、不以摘要替代适用原文。
- 普通问候、闲聊、翻译、简单计算和脱离项目的概念解释直接回答，不加载工程正文、不扫描项目、不初始化任务状态。不因新对话自动运行恢复脚本。
- 用户当前明确要求优先；仅换实现不重做设计。无相反要求的新设计用 shadcn/ui + Tailwind CSS，图标统一 Morphicons；默认栈不得覆盖指定框架或源码原貌。
- 自动调用不扩大授权：只读不写入，保护我的已有改动、数据、密钥和正常旧行为；高风险写入按原规范说明影响、验证与回滚并取得确认。
- 技能缺失、被禁用或读取失败时，说明未启用及具体原因，不冒充已经按规范执行；不要在每次聊天中自动下载或重新安装。
- 实现任务先更新当前项目根目录 `工作流程.md`（不是 Codex/技能目录），逐项待做、进行中、验证后打勾；新增追加，续作先读，保留历史；小改也记，未授权只读不写。
<!-- production-engineering:auto:end -->
```

## 写入边界

通常只合并到当前 `CODEX_HOME` 下的 `AGENTS.md`；未设置时为 `~/.codex/AGENTS.md`。已有非空 `AGENTS.override.md` 时，按教程同步同一短块到实际生效文件，保留其他规则并说明覆盖关系；不能删掉覆盖文件或谎称两个文件都会加载。

不把完整规范、技能正文、来源索引或全部切片复制到这里。没有本机写权限时，提供这段已填好真实路径的内容和唯一待办；不得报告已写入。刷新后仍需用新会话和工具记录验证，不能仅凭助手自称已使用。
