# 个性化自动调用指令

默认安装同时配置这里的短调度规则和本机技能，不再把个性化接入当成可省略步骤。用户另行明确要求“只安装技能，不修改个性化”时，保留该限制并说明未完成接入。

桌面端“设置 → 个性化 → Codex 说明”对应个人 `AGENTS.md`，不是另一份需要重复安装的技能。AI 应按[安装教程](ai-installation.md)核实实际文件、备份并**直接合并**短调度块；具备本机写权限时不能只把模板交给用户自己粘贴，也不能用本文件全文覆盖用户已有内容。

## 旧长版必须收口

如果现有 Codex 说明同时出现 `# 全局 Codex 工作规则`、`## 自动使用生产工程技能`、`本机兜底路径`、`## 小白优先沟通`、`## 轻任务优先` 等旧模板特征，不能继续和新短块并存。按[旧长版个性化迁移](legacy-personalization-migration.md)先备份，再把明确属于本 Skill 的旧长工程块替换为当前短调度块；旧块之外的用户规则原样保留。不能只在文件尾追加新块，让两套规则长期同时生效。

## 要合并的短规则

下面代码块与仓库根目录的 [global-AGENTS.example.md](../global-AGENTS.example.md) 是同一模板，不是两套规则。短块只绑定稳定技能名 `$production-engineering`，**不写入 `SKILL.md` 绝对路径**；真实安装目录由安装流程单独核实并用于验证和报告，不固化进个性化。升级时只更新标记块，不重复追加。

```markdown
<!-- production-engineering:auto:start -->
# 工程技能自动调用

工程技能：`$production-engineering`

- **每轮先做**：收到用户新消息（含中途补充），先把新要求写进当前对话项目根目录的 `工作流程.md`（没有就建）。中途补充即记入清单算必做，全做完才停：回复前对照清单，有待做就继续，不问是否继续；只缺用户才能给的信息时才停。
- 用户让 AI 看、改、修、跑、继续、提交，做 UI、SEO/收录、同步上游、二开模板、先列清单、字段清单、别写死、前端交付、视觉验收时，结合当前项目主动用技能；“这个太丑了”“跟原站不像”“按钮没反应”也适用。
- 用户只需说想要的结果；用户已给源码先读相关实现，源码可查的不反问，其余技术事实由 AI 自己查。关键歧义查证后再问并给推荐。
- 普通问候、闲聊、翻译、简单计算、只问不改的代码解释直接回答。命中技能不等于全仓扫描、扩大权限；“随便/你看着办”不是无限授权。
- 用户当前明确要求优先；仅换实现不重做设计。原业务逻辑、接口、权限、数据和流程默认锁定；重构/优化/UI 重写不授权改结果。旧业务/接口/权限/数据/配置/客户端先兼容共存，验证后再淘汰。
- 所有写入核对当前聊天关联源目录；清单不是 Codex/技能目录，不跨项目共用。只提一件小事可不建清单，进度面板用户要看才开；保留历史。不清库、不重建现有数据库。
- 未授权只读不写；不盲试，生产后端关键失败留脱敏日志。明确授权不重复确认；汇报用人话少术语；详细流程只在 Skill。
<!-- production-engineering:auto:end -->
```

## 写入边界

通常只合并到当前 `CODEX_HOME` 下的 `AGENTS.md`；未设置时为 `~/.codex/AGENTS.md`。这里的 `AGENTS.md` **只保存调度指令**；业务 `工作流程.md` 必须放在当前对话正在开发的项目根目录，不能放进 `CODEX_HOME` 或技能目录。已有非空 `AGENTS.override.md` 时，按教程同步同一短块到实际生效文件，保留其他规则并说明覆盖关系；不能删掉覆盖文件或谎称两个文件都会加载。

不把完整规范、技能正文、来源索引或全部切片复制到这里。没有本机写权限时，提供这段**不含机器绝对路径**的短块和唯一待办；不得报告已写入。刷新后仍需用新会话和工具记录验证，不能仅凭助手自称已使用。
