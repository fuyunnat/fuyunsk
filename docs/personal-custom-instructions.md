# 个性化自动调用指令

默认安装同时配置这里的短调度规则和本机技能，不再把个性化接入当成可省略步骤。用户另行明确要求“只安装技能，不修改个性化”时，保留该限制并说明未完成接入。

桌面端“设置 → 个性化 → Codex 说明”对应个人 `AGENTS.md`，不是另一份需要重复安装的技能。AI 应按[安装教程](ai-installation.md)核实实际文件、备份并**直接合并**短调度块；具备本机写权限时不能只把模板交给用户自己粘贴，也不能用本文件全文覆盖用户已有内容。

## 旧长版必须收口

如果现有 Codex 说明同时出现 `# 全局 Codex 工作规则`、`## 自动使用生产工程技能`、`本机兜底路径`、`## 小白优先沟通`、`## 轻任务优先` 等旧模板特征，不能继续和新短块并存。按[旧长版个性化迁移](legacy-personalization-migration.md)先备份，再把明确属于本 Skill 的旧长工程块替换为当前短调度块；旧块之外的用户规则原样保留。不能只在文件尾追加新块，让两套规则长期同时生效。

## 要合并的短规则

下面代码块与仓库根目录的 [global-AGENTS.example.md](../global-AGENTS.example.md) 是同一模板，不是两套规则。短块只绑定稳定技能名 `$production-engineering`，**不写入 `SKILL.md` 绝对路径**；真实安装目录由安装流程单独核实并用于验证和报告，不固化进个性化。升级时只更新标记块，不重复追加。

```markdown
<!-- production-engineering:auto:start -->
# 工程技能自动调用

工程技能：`$production-engineering`

- 默认中文；命令、路径和技术标识保留原样。
- 用户让 AI 看、改、修、跑、继续、对比、同步上游、SEO/收录、二开模板、先列清单、字段清单、别写死、补功能或提交，就主动用 `$production-engineering`；“这个太丑了”“这里不对”“继续”“旧模板别动”“按钮没反应”等口语短句也结合项目理解。
- 用户只需说结果；能从源码、配置、Git 和运行方式查明的技术细节由 AI 自查。若存在会导致明显不同结果的合理理解，先用人话给 2–3 个结果选项和推荐；选过后不重复确认。
- “随便/你看着办”只表示在已确认范围内自由决定，不授权删功能、换框架、跨项目、高风险写入或扩大业务范围。
- 只加载当前阶段必要规则；有源码/演示站先核对真实实现。命中技能不等于全仓扫描、扩大权限或自动恢复旧任务。
- 普通闲聊、翻译、计算和脱离项目的概念解释直接回答。
- 最新明确要求优先；仅换实现不重做设计。新设计无相反要求时用 shadcn/ui + Tailwind CSS，图标 Morphicons；指定框架和源码原貌优先。
- 写前核对项目根，越界停；旧业务/接口/权限/数据/配置/客户端先兼容共存；二开同步只补丁吸收目标上游改动，不整文件覆盖或默认整仓 merge/rebase；不盲试，生产关键失败留脱敏日志；高风险先确认。
- 实现依赖的详细清单落到 `PROJECT_ROOT/工作流程.md`，不能只留聊天；续作先读、验后勾选，不跨项目共用；纯只读不写。
<!-- production-engineering:auto:end -->
```

## 写入边界

通常只合并到当前 `CODEX_HOME` 下的 `AGENTS.md`；未设置时为 `~/.codex/AGENTS.md`。已有非空 `AGENTS.override.md` 时，按教程同步同一短块到实际生效文件，保留其他规则并说明覆盖关系；不能删掉覆盖文件或谎称两个文件都会加载。

不把完整规范、技能正文、来源索引或全部切片复制到这里。没有本机写权限时，提供这段**不含机器绝对路径**的短块和唯一待办；不得报告已写入。刷新后仍需用新会话和工具记录验证，不能仅凭助手自称已使用。
