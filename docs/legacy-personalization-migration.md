# 旧长版 Codex 个性化迁移

本规则用于把早期 `production-engineering` 安装时写进“Codex 说明”的大段工程规范，收口成当前的轻量自动调用块。目标是：**个性化只负责识别任务和调用 Skill，完整工程规则只在 Skill 内按需加载。**

## 一、识别旧长版，不能只凭一个关键词误删

只有同时出现多个旧模板特征，才能把一段内容判定为本 Skill 的旧长版，例如：

- `# 全局 Codex 工作规则`
- `## 自动使用生产工程技能`
- `本机兜底路径`
- `## 小白优先沟通`
- `## 轻任务优先`
- 大段 Git、交付、轻量通道、部署确认等生产工程规则直接写在个人 `AGENTS.md` 中

只出现“默认中文”“Git”“部署”等普通词不能据此删除。无法确认来源、或旧块里混入了用户独有且无法安全分离的规则时，先保留并报告冲突；不要整文件覆盖。

## 二、升级时必须先备份，再做瘦身

1. 核实实际 `CODEX_HOME`、个人 `AGENTS.md` 和是否存在非空 `AGENTS.override.md`；按 Codex 当前优先级确定真正生效文件。
2. 修改前分别建立带时间戳备份，记录原路径与备份路径。
3. 从同一版本仓库的 `global-AGENTS.example.md` 读取短调度块，把 `<已核实的SKILL.md绝对路径>` 替换成当前真正安装的 `SKILL.md` 路径。
4. 旧长版里写死的历史技能目录、过期章节路径和重复工程规则不继续保留；新的短块只引用当前有效 Skill。

## 三、旧长块和新短块不能共存

升级结果只能有一套 `production-engineering` 个性化入口：

- 已有 `production-engineering:auto:start` / `production-engineering:auto:end` 时，更新该标记范围。
- 明确属于旧版 `production-engineering` 的长工程块，替换成当前短调度块，不能只在文件尾再追加一份新块。
- 旧长块之外的用户个人习惯、其他 Skill 规则、公司规则和与本 Skill 无关的内容原样保留。
- 如果用户自己在旧长块内部增加了独有规则，优先把这些独有规则移到短块之外继续保留；不能确定语义时不要猜删。
- 不新建 `AGENTS.override.md` 来绕过旧内容，也不改变现有覆盖优先级。

最终不应再让每轮对话都携带整套生产工程正文；详细 Bug、数据库、SEO、模板二开、规划清单、Code Craft、配置化等规则继续由 Skill 路由按需加载。

## 四、专门处理桌面“Codex 说明”旧缓存

桌面“设置 → 个性化 → Codex 说明”对应个人规则文件。写入磁盘后：

1. 重新读取文件，确认旧长工程块已经不存在，只剩一个当前短块。
2. 如果界面仍显示旧内容，先重新打开设置或刷新客户端，**不要把旧界面内容再次点保存覆盖新文件**。
3. 必要时在用户保存工作后正常退出并重开 Codex；不强杀应用。
4. 重新进入“Codex 说明”核对显示内容与磁盘一致。

## 五、验收门槛

迁移完成至少满足：

- 当前生效个人规则中只有一个 `production-engineering` 短调度块。
- 不再存在上述旧长版标题、`本机兜底路径` 或另一整套重复工程规则。
- 短块中的 `SKILL.md` 绝对路径真实存在且指向当前安装版本。
- 与本 Skill 无关的用户规则与修改前一致。
- `global-AGENTS.example.md` 和 `docs/personal-custom-instructions.md` 的短块保持同源。
- 新会话里“修一下”“先列清单”“旧模板别动”“别写死”等工程意图能触发 Skill；普通闲聊不加载工程条款。

没有本机文件权限时只能给出已填好真实路径的短块和迁移步骤，不能声称已经修改用户的 Codex 说明。
