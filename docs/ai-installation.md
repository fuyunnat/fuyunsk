# AI 自动安装、个性化接入与升级

本教程交给**运行在目标电脑、具备本地文件权限的 AI**执行。默认交付是“本机技能 + 个性化短指令 + 验证”，不是只下载一个目录。仅有 GitHub 访问权限的远端会话不能代替本机安装。用户明确要求只装技能时，不改个性化并标记该步骤未执行。

## 一、先确认范围与真实位置

读取仓库 `README.md`、本教程和[个性化模板](personal-custom-instructions.md)。先简短报告准备改什么，安装、接入、验证各完成一阶段就报告实际结果；不要长时间无反馈，也不要输出密钥或完整配置。

确认当前客户端、运行主机、用户主目录、实际 `CODEX_HOME` 和技能列表。不能把终端环境等同于桌面应用环境；未设置 `CODEX_HOME` 时，个人规则默认在 `~/.codex/AGENTS.md`。桌面“个性化 / Codex 说明”编辑的是个人 `AGENTS.md`，不是本仓库根目录的维护规则。

只检查候选技能根目录和当前项目相关路径。当前官方用户级目录为 `~/.agents/skills`；旧安装可能在 `~/.codex/skills` 或自定义位置。结合客户端技能列表、配置及真实文件确认有效位置，不扫描整个磁盘、不在每个候选目录都装一份。

读取个人 `AGENTS.md`、已有 `AGENTS.override.md` 及当前项目适用规则，确认是否有旧的显式调用限制、同名技能禁用项或托管策略。只查看必要配置项，不打印认证信息；不能绕过管理员禁用或用修改权限配置来启用技能。

## 二、备份并安装一份完整技能

从 `fuyunnat/fuyunsk` 的 `main` 获取最新内容，记录具体提交 SHA；本次下载的文档、模板和技能使用同一提交，避免升级中途混用版本。先暂存、检查来源与所需文件，不使用未经审查的远程脚本直通执行。

对旧技能、将修改的个人规则和符号链接目标建立带时间戳的可恢复备份，记录对应关系。备份放在技能扫描目录之外，避免备份也被识别成同名技能。已有本机定制先比较；无法判断如何保留时只问这一处冲突，不直接覆盖。

优先使用当前可用的 `$skill-installer` 或客户端支持的安装方式。它只负责技能文件时，仍须继续完成第三步，不能提前报告安装结束。没有该工具时，可用已审查的下载和复制方式原位安装；完整复制 `skills/production-engineering/`，不要只复制 `SKILL.md`。

同名技能只保留一份有效安装。确认重复后把旧副本移到上述备份位置；禁止永久删除，也不触碰其他技能。核实符号链接实际指向，不能覆盖根目录、空路径或其他项目。只有确定当前客户端不识别旧位置时才迁移，并更新短指令路径。

核对 `agents/openai.yaml` 中 `allow_implicit_invocation: true`。若本机存在仅针对该技能的禁用项，先说明；用户授权启用且不受托管限制时，仅备份并调整该精确条目。不得顺手修改 API Key、模型、MCP、插件、记忆、沙箱、审批模式、全局信任或其他无关配置。

## 三、必须接入个性化自动调用

默认安装必须完成本步骤，不能只说“把这段自己粘贴进去”。

1. 取仓库根目录 `global-AGENTS.example.md` 的短标记块，填入刚核实的技能 `SKILL.md` 绝对路径，不能留下占位符或指向临时下载目录。
2. 在已备份的个人 `AGENTS.md` 中合并这一个块。已有 `production-engineering:auto:start` / `production-engineering:auto:end` 标记时，只更新对应范围；首次安装追加一次。重复标记先去重，损坏或边界不明确先确认。保留块外所有无关要求，不整文件覆盖。
3. 对明确属于本技能旧版本的“必须手写技能名才启用”、禁用自动调用或重复长工程块，逐段确认来源后替换为短调度；无法确认归属或包含独有要求时保留并报告冲突，不能按“包含工程二字”批量删除。
4. 如果已存在非空 `AGENTS.override.md`，它优先于同目录 `AGENTS.md`。个人输入框对应文件仍保留短块，同时把**同一短块**合并到这个已存在的实际生效覆盖文件，分别备份且保留各自其余内容；这一层运行时只选一个文件，不是加载两份。不得新建覆盖文件、改变优先级或删除原覆盖规则；受保护或存在冲突时暂停该步并说明。
5. 重新读取保存后的精确范围，确认短块每个目标文件只有一份、路径存在、原规则仍在。界面可操作时重新打开个性化核对显示；不要把界面旧缓存再次保存覆盖磁盘新内容。不能访问界面时，分别报告“文件已写入”和“界面未验证”。

全局短块只负责语言、任务识别和调用入口。完整原文、全部切片、任务日志不放进个性化；不要每轮联网更新、不启动额外 MCP 或后台服务、不为提速删验收标准。

## 四、分开验证文件与实际调用

**文件验证**：确认有效技能目录包含 `SKILL.md`、`agents/openai.yaml`、`references/source-original.md`、`references/source-speed.md`、`references/source-lock.json`、`references/rules/`、`references/rules-speed/`、`references/rules-manifest.json`、`references/rules-index.md` 、`references/frontend-stack.md`、`scripts/rule-batch.js` 和 `scripts/read-rules.js`；与本次固定提交的对应文件校验一致。确认短块写入位置、路径、覆盖关系和重复副本处理结果。

有 Node.js 时，先检查脚本再执行只读验证：

```bash
node "<技能目录>/scripts/read-rules.js" --list
node "<技能目录>/scripts/read-rules.js" --id 00-00 --json
```

在下载的完整仓库根目录可运行 `node scripts/validate-skill.js`，主自检已经包含原文重建等检查，不必再重复跑一遍。正常使用不运行生成器；安装时无 Node.js 可直接读文件并比较校验值，标记脚本未执行，不因此安装无关依赖。

**实际调用验证**：刷新客户端；必要时请求用户保存工作后退出重开，不强杀应用。使用安装后的同一配置，在全新会话或独立 CLI 会话中执行少量只读测试。测试不提技能名、不临时注入调度规则，避免把显式提示当成自动调用证据。

| 测试输入 | 检查工具轨迹和结果 |
| --- | --- |
| `你好` | 中文回应，不为本技能读取工程条款或初始化任务状态 |
| `检查当前测试项目的页面结构，只读，不改文件。` | 自动读取已安装技能入口和必要条款，而不是仅声称使用 |
| `审查当前测试项目有没有明显代码问题，先别修改。` | 能进入审查流程，同时保持只读 |

测试使用无敏感信息的独立小项目，不能拿生产操作或真实用户数据验证。缺少新会话控制、CLI、权限或模型访问时，明确“文件安装已完成，实际自动调用待验证”，给出一个必要下一步；不要让用户重新做 AI 已能完成的安装步骤。显式 `$production-engineering` 仅用于调用失败后的定位，不能算自动触发通过。

新增页面验收还要确认当前规则是 shadcn/ui + Tailwind CSS，不再把原稿 Vue/Ant 默认当作新页面选型。只读检查批量命令可以使用 `--stage 只读 --topic 前端`；这只验证读取，不执行页面创建或迁移。

## 五、完成报告与恢复

用中文简短报告：来源提交 SHA、有效技能绝对路径、个人规则与实际生效文件、备份位置、移出的重复项、命令与结果、界面是否核对、实际自动调用是否验证及剩余待办。只有有对应证据时才写“安装、个性化接入和自动调用都已验证”。

失败时保留旧备份和新文件，不永久删除；只恢复本次改动的技能和短块，保留安装后用户的新修改。恢复规则前对比差异，不能直接用整文件旧备份覆盖新要求。仓库更新不等于用户电脑自动升级。

## 六、速度与官方依据

相同客户端、模型、推理设置、项目及网络下重复少量前后对照，区分首次加载、缓存和上游波动。文件读取耗时不等于模型首字延迟，不承诺所有请求秒回；不为跑分更改用户配置。

安装路径和覆盖行为以当前客户端实际情况及官方文档为准：[个性化设置](https://developers.openai.com/codex/app/settings)、[个人与项目指令](https://developers.openai.com/codex/guides/agents-md)、[技能目录和自动调用](https://developers.openai.com/codex/skills)。这些是客户端机制说明，不替代用户原始工程规范。
