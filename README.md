# fuyunsk：中文工程技能

这是按用户完整自定义指令组织的中文 `production-engineering` 技能，用于真实工程实现、修复、前端界面、代码审计、验证、Git 交付、数据库和部署。

**保留原文，不靠删规则提速。默认安装同时接好个性化短指令与本机技能：工程任务自动调用，普通聊天不加载工程正文。**

## 个性化怎样自动调用技能

```text
个性化 / Codex 说明中的短调度规则
    → 按工程目标自动调用本机 production-engineering
    → 读取 SKILL.md
    → 按当前领域和阶段读取原始规范条款
```

不要求你每次手写技能名。个性化短块负责调用，技能保留完整规则；**只安装技能文件、不接入短规则，不算完成本仓库的默认安装流程。** 用户明确要求不改个性化时除外。

桌面个性化与个人 `AGENTS.md` 是同一配置链路，不要当成两个独立地方各塞一整份规则。默认位置是 `~/.codex/AGENTS.md`，自定义 `CODEX_HOME` 或覆盖文件按[安装教程](docs/ai-installation.md)核实；[个性化模板](docs/personal-custom-instructions.md)由 AI 直接合并，短块只保存稳定技能名，不嵌入固定安装目录。真实技能路径由安装流程另外核实，用于验证和报告，保护其他原有指令。

**特别注意：`~/.codex/AGENTS.md` 只保存全局个性化/调度规则。业务 `工作流程.md` 不是 Codex 全局配置，也不是 Skill 安装产物。安装或升级本技能时不要创建它；只有开始某个具体工程实现任务后，才在该对话实际目标项目根目录创建或更新。**

## 使用方法

直接描述工程目标，例如“修一下这个页面的按钮，只改本地并验证”。需要明确点名或排查匹配时可写：

```text
$production-engineering 做一个后台配置页，沿用当前项目技术栈。
$production-engineering 检查这个仓库有没有漏洞，先不要改文件。
```

自动匹配取决于客户端与模型，不把静态测试通过当作所有真实请求均命中的保证。

## 跨项目误覆盖保护

所有业务写入都受[项目写入边界](skills/production-engineering/references/project-write-boundary.md)约束，不只保护工作清单。AI 先固定聊天项目真实根与身份，再核对文件、工具工作目录、复制解压和构建输出；不因临时 `cd`、参考源码中的路径或相同父目录改选其他项目。目标存在无关文件时不覆盖。

`project-path-check.js` 提供只读、批量、失败即退出的路径预检；它不是沙箱，不能拦截绕过检查器的写入。安装时另查宿主实际可写范围，不自动改权限或恢复事故文件。安装与升级必须继续执行[写入边界安装验收](docs/project-boundary-installation.md)。原稿、动态清单、源码原貌与 Git 授权不变。

## 项目根目录工作流程

**以当前聊天项目关联的源文件夹为准，不是 Skill 所在目录。** 先核实当前对话正在开发的目标项目根目录。`PROJECT_ROOT` 只是文档里对这个已确认目录的简称，不是 `~/.codex` 下的目录，也不是要新建一个名为 `PROJECT_ROOT` 的文件夹；清单实际路径就是 `<当前对话项目根目录>/工作流程.md`。这里不是内部 `src/` 子目录，也不是临时终端目录；读取技能或 `cd` 到工具目录不改变清单位置。多个项目各自保管，不共用一份总表；关联多个源目录但归属不明时，只问具体目录。

本仓库根目录的 `工作流程.md` 只记录 fuyunsk 自身维护，不是安装后的业务清单。它不应复制到技能安装目录并作为各项目共同进度；安装仅包含 `skills/production-engineering/`，其中 `templates/workflow.example.md` 是空白格式，不是实际任务。

直接给目标即可由 AI 建立并持续补全清单，不必先逐项审批；明确要求先确认时例外。目标内的旧功能、联调、失败场景及验收漏项先追加依据再推进；范围外内容和缺失授权另行确认，不能凭初版清单勾完就宣布完成。已经开工时补建清单，不清空或重做已有正确成果。

这里的“根目录”是当前正在开发的目标项目根目录，不是 `CODEX_HOME`、`~/.codex/` 或 Skill 安装目录。多项目仓库按实际子项目定位；参考源码与目标工程分开时写在目标工程，不能改参考副本。

普通实施由 AI 在**目标项目根目录 `工作流程.md`**维护可见清单；快速小改（改文案、调样式、修一个明确的小问题）不建清单，只在对话里说一句。需要清单的任务一般一至三项，活跃区块以 10 行以内为目标；多阶段摘要以 40 行以内为目标，详细需求和旧历史保留并按需读取。

用户明确要求清单原文恢复、不追加记录或禁止写入时，在对话中报告状态，不先写新任务、不恢复后补记录。明确放弃指定代码改动并要求不备份时直接按核实范围恢复；数据库、`.env`、上传与未授权文件仍受保护。授权例外统一见 [source-policy.md](skills/production-engineering/references/source-policy.md)。

```markdown
- [ ] W001【待做】待开始的具体事项。
- [ ] W002【进行中】正在处理的事项。
- [ ] W003【待验证】代码已写完，尚未验证。
- [x] W004【已完成】实际完成且验收通过；证据：可核对结果。
- [ ] W005【阻塞】写明失败或缺失条件，不能提前打勾。
```

接到新任务先追加事项，做完一项及时更新一项；新增需求继续追加，不删未完项和历史。换会话、上下文压缩或问进度时，先读当前任务区块，再核对真实文件。源码基线、改变项、保留项和下一步也放在该区块，不靠聊天记忆。

普通聊天不建文件；只读不写，除非明确单独授权清单。只维护少量增量文字，不因此新增后台服务、额外模型调用或每轮全仓扫描。清单不替代测试、旧任务快照或迁移台账，复杂任务只建立关联，避免三份独立待办。

见[工作清单规则](skills/production-engineering/references/workflow-checklist.md)和[空白模板](skills/production-engineering/templates/workflow.example.md)。本仓库根目录的[工作流程](工作流程.md)是自身维护历史，安装到别的项目时不能复制成它们的完成记录。

## 已提供源码：先读、按要求改，不擅自重做

用户已给源码，不等于还要用户从头描述一遍。技能先读取相关页面、样式、资源和行为实现，用实际路径/版本说明依据，区分本次改变项、必须保留项与验证方式；不把列过目录、读过 README 当作看过实现。

“保留原样，换一种框架或语言”只改变实现方式，不授权重新设计。用户明确目标优先于默认选型；HTML 改成 Vue 是示例，不是要求所有新项目改用 Vue。无相反明确要求的新设计仍默认 shadcn/ui + Tailwind CSS。保留原貌时复用源码中的布局、CSS、资源和交互，再做新旧对照；构建通过不等于外观一致。

源码能查明的先查；真实版本冲突、缺失资源、需求歧义在查证后仍影响结果时，只问具体阻塞点并暂停相关修改。不重复索要可访问的源码，不把“无法运行”说成“没有提供”，不以用户未回复默认批准。已明确且相容的要求直接执行，不额外制造确认轮次。关键决定随已有任务检查点恢复，不另起常驻服务或每轮全仓扫描。

本次优化是指令边界与读取路径修复。维护自检只证明规则文案、模板一致性和读取链路；不能保证模型实际逐次服从，也不能冒充已经对用户 HTML/Vue 页面做了视觉验收。

完整通道保留原文条件式任务分支推送和评审流程；只读、小改、不具备远端条件等按原文处理。**提交或推送不等于允许合并主线、强推、删除远端分支或操作生产。**

本次用户已明确更改前端选型：[当前前端规则](skills/production-engineering/references/frontend-stack.md)替代原稿的 Vue/Ant 默认，不是再加一套可选方案。原稿保留用于追溯，其他工程规范不变。

## 图标统一方案

图标统一通过 [Morphicons](https://www.morphicons.com/) 接入；它负责描边 SVG 的渲染与变形，图形数据仍可来自官网兼容的 Lucide、Tabler、Heroicons 等来源，不是只改一个依赖名称。React、Vue 和普通 JavaScript 按真实框架选择官方入口，不为图标迁移框架。完整边界见[前端选型中的图标规则](skills/production-engineering/references/frontend-stack.md#图标统一使用-morphicons)。

新设计与授权新增/替换的图标执行统一方案；原样迁移不擅自改变旧图标、样式或交互。不强制增加动画，明确处理减少动画偏好；找不到兼容图形或确实与保留要求冲突时，先查证再问，不偷换其他库。

AI 安装或升级技能时，同步更新前端规则和个性化短块中的 Morphicons 要求，但**不安装业务依赖**、不改当前业务项目、不另加后台服务。实际开发需要时才在目标业务项目接入，具体版本与许可证按对应来源核实。这里的规则检查不等于已在用户项目验证实际图标效果。

## 本地 AI 工作进度面板

想看进度时说一句“打开进度面板”或“看看进度”，AI 核实项目根后启动并给你地址：正常就复用，离线则启动本地守护，运行中退出也会恢复。平时不会在后台自动开启；闲聊、安装/升级及明确停用时不启动。紧凑工作台左侧列出可搜索的项目/任务记录，中间展示当前步骤和执行流程，右侧集中放目标、阻塞、验证证据与停止条件。AI 更新 `工作流程.md` 后自动刷新；手选历史任务保留选择，不新增另一套进度数据。

```bash
node <实际技能目录>/scripts/progress-panel-service.js --ensure --project "项目甲=/绝对路径/项目甲" --project "项目乙=/绝对路径/项目乙"
```

浏览器打开命令返回的真实地址，默认从 `http://127.0.0.1:4318` 起选择可用端口；用同一命令将 `--ensure` 换成 `--stop` 停止守护。仅 Node.js 标准库，只读指定清单，不创建缺失文件、不扫描电脑、不启动业务后端。安装脚本会携带技能内的脚本与页面资源。

面板显示已记录进度，不能看见 AI 内部思考或自动获取全部聊天；同一项目不同对话用独立任务区块，可选写 `对话：任务名称`。清单未更新时看最后修改时间，连接断开标明旧记录；计数不代表全项目功能覆盖或验收保证。守护只恢复面板自身，60 秒内连续 5 次退出后停止重试，不关闭占端口的其他服务。详情见 [面板规则](skills/production-engineering/references/workflow-progress-panel.md)。

执行流程下还有三个工具：**改动地图**按当前任务已记录的 Git 基准比较；没有基准就明确展示项目未提交改动，不归因于本轮。**验收证据**展示事项记录及清单明确链接的项目内截图/日志。**快捷提示词**一键复制“完成后停止、本批收尾、只读检查、展示差异、暂停收尾”，携带最新清单目标，粘贴到对应对话后生效。“本批收尾”用于明确修改目标、停止继续扫描并交付现有补丁；面板不会执行这些指令或操作业务数据库。

## 团队 Git 交付

提交、推送、评审和回滚阶段会自动同批读取[团队 Git 交付专项](skills/production-engineering/references/git-team-delivery.md)，普通只读、实现和验证阶段不常驻加载，因此不会把日常开发重新变成重流程。

专项强调按**可审查、可验证、可回滚的逻辑单元**提交；远端保存、PR 和进入正式主线分别汇报，不能把“已推送”说成“已进入 main”。多人协作时先固定真实远端基线，主线或 PR head 被别人更新就重新比较，不能用盲目 merge/rebase、`ours/theirs` 或强推覆盖团队的新工作。

用户明确要求“提交到 main / master”或“合并到主库”时，才允许当前已说明的改动进入主线。执行前重新确认远端主线 HEAD、实际 diff、验证/CI 和回滚点；只允许正常快进或仓库允许的合并方式。最后确认后主线又移动就停止并重新比较，不用 force 抢写。

每个 Git 检查点必须用中文说明实际 commit、分支或 PR、验证结果、**是否已经进入稳定主线**以及如何恢复，避免只扔一个 hash 让用户自己判断状态。

## 减少实际等待

已确定阶段与领域时，一次取齐原文和专项说明，不再强制串行经过入口、路由、索引、通道：

```bash
node "<技能目录>/scripts/read-rules.js" --stage 小改 --topic 内容
node "<技能目录>/scripts/read-rules.js" --stage 实现 --topic 前端,接口
node "<技能目录>/scripts/read-rules.js" --stage 只读 --topic 审计
```

这只是批量读取，不自动选择权限或执行命令；小改必须满足原文快速条件。验证、提交、推送等后续阶段只取当前所需；新任务从中途开始时追加 `--topic 通用,适用方式`。没有 Node.js 时用批量文件读取，不为此安装依赖。具体实现与对照办法见[运行延迟说明](docs/runtime-latency.md)。

减少工具往返不等于保证模型更快：较大的同批输入也可能增加模型处理时间，需测完整任务。已在上下文且未变的规则不重读；必要的验证、状态记录和授权不删。只合并独立检查，有依赖或共享写入的步骤保持顺序。

## 速度从哪里来

初始匹配只需要简短名称与描述；选中技能后读取短入口。原文已在维护阶段拆好，运行时只读当前领域和阶段的片段，不启动生成器、不联网拉规则、不默认恢复任务、不反复扫描或运行相同检查。完整任务仍须覆盖所有适用条款。

[只读条款助手](skills/production-engineering/scripts/read-rules.js)是可选工具，无第三方依赖；也可以直接用文件工具读取切片。文件体积和本地读取基准不等于模型端到端速度，实际改善需要在同一环境对照测量。

## 本机环境诊断（只读）

安装/升级后，在本仓库根目录使用 `node scripts/doctor.js` 或 `node scripts/doctor.js --json`；在已安装的单份技能中使用 `node <实际技能目录>/scripts/doctor.js --json`。它只检查已知候选安装路径、原稿校验、重复副本和个性化短调度，不联网、不改配置、不会创建业务任务清单。诊断结果**不代表真实 Codex 已自动调用技能或桌面 UI 已刷新**。详见 [安装文档](docs/ai-installation.md)。

## 安装和升级

[安装教程](docs/ai-installation.md)是给 AI 执行的完整流程，覆盖固定版本下载、原位安装、备份去重、个性化接入、覆盖规则处理和新会话验收。[短全局模板](global-AGENTS.example.md)与[个性化模板](docs/personal-custom-instructions.md)内容相同，只合并一个标记块，不重复追加。

默认安装时，有本机写权限的 AI 必须同步更新“个性化 / Codex 说明”对应的个人规则，不能只安装 Skill 后把模板交给用户。短块按 `$production-engineering` 技能名调用，不写死机器路径；实际安装目录单独验证。

安装完成不等于自动调用已验证。AI 必须区分文件、界面和新会话的实际证据；不能仅凭自己的回答判定成功。更新 GitHub 不会自动更新你本机的技能或个性化。

## 整项目换语言与防遗漏

整项目重写、换开发语言或全量架构迁移使用[迁移专项](skills/production-engineering/references/project-migration.md)，普通小改不加载。AI 先固定旧版并盘点页面、接口、权限、任务、回调、数据和部署入口，再建立“旧能力 → 新实现 → 必需用例 → 执行证据”的对照。

实际迁移时，按模板建立盘点基线和迁移台账，绑定到任务状态。`check` / `finalize` 会核对每个旧功能、对应验收、代码指纹、恢复演练和阻塞；缺项不能靠一次普通命令成功宣布完成。保留旧实现只算阶段性共存，废弃必须有批准证据；生产切换另行授权。

```text
把这个项目从当前语言迁移到目标语言，业务行为保持兼容。
先盘点旧功能、确认边界与目标版本，建立迁移台账并绑定到任务状态。
分模块验证，保留旧实现；中断后从记录恢复，不直接删除旧项目或切换生产。
```

台账模板和检查程序随技能完整安装；无敏感的迁移文档是否入库按项目约定，不能只放在不可同步的聊天里。代码、权限、数据库和前端 shadcn/ui + Tailwind CSS 要求继续适用。工具只检查已登记范围与凭据，不保证盘点绝无遗漏或模型永不遗忘。

## 复杂任务执行编排

大型、多阶段、多个相对独立子任务或确实需要独立复核时，按需加载[代理执行规则](skills/production-engineering/references/agentic-execution.md)，普通 Bug、小改和简单文档不会因此变重。

这层能力包括：先审现有计划而不是机械照单执行；用户已经授权完整目标时持续做到阻塞/完成；子代理只拿最小必要上下文；**独立任务才并行**，共享文件、数据库、状态或顺序依赖保持串行；重大实现按“需求符合 → 代码质量”双阶段 review；收到 review 先验证源码和测试再改；完成声明使用最后一次相关修改之后的 **fresh verification**，不拿旧 CI、旧测试或子代理一句“done”冒充证据。

复杂任务还会区分探针、边界型和架构型工作，防止明确小改被拉成长设计会；多步骤计划要写清依赖、接口和独立验收；异步等待能等状态/事件就不靠固定 sleep 猜时间。worktree 只在确有隔离价值且获得对应授权时使用，主线合并、强推、删除远端仍需单独授权。

本能力审查并吸收了 `obra/superpowers` 的 14 个开发类 Skill，但没有安装它作为运行依赖，也没有照搬会拖慢当前工作流的绝对规则。逐项“吸收 / 已有等价 / 刻意不采用”的对应关系见 [Superpowers 方法吸收映射](docs/superpowers-method-absorption.md)。

## 验证（仅维护本技能）

日常使用本技能修改其他项目时，运行那个项目的测试与验收，不运行这里的生成器、自检或测速。修改本仓库、生成规则或检查安装完整性时，运行：

```bash
node scripts/validate-skill.js
git diff --check
```

主自检已包含 `build-rules.js --check`，无需重复执行；只排查切片一致性时才单独运行该命令。含新增文件的提交还要检查已暂存差异。测速是可选维护任务：`node scripts/benchmark-rule-loading.js --runs 7`，不属于日常业务流程。

校验包含原稿锁定、逐段重建、主题读取、中文入口、路径与错误处理、状态助手、秘密与产物检查。程序测试不代表真实 Codex 行为测试；安装后的触发、中文交付和实际耗时需按教程另行验收。

## 前端设计智能

明确说“重新设计、太丑了、高级点、精修一下、UI/UX 审查、做套设计系统”时，按需加载[前端设计智能规则](skills/production-engineering/references/frontend-design-intelligence.md)。普通 Bug、普通前端功能开发和严格原样迁移不会因为项目有前端就自动加载这一层。

这层能力融合了 7 类前端设计 Skill 的有效方法：先判断品牌型/产品型设计语域，用 VARIANCE / MOTION / DENSITY 三个设计旋钮约束方向；设计选择优先依据用户参考、现有品牌/Design System 和真实产品任务，不随机套热门模板；界面精修区分 Critique / Polish / Distill / Harden，不把所有“不够好看”都解释成整页重做。

产品 UI 会重点检查排版、密度、状态连续性、键盘与无障碍、表单、错误恢复、移动端、长文本、safe area、loading/empty/error 等不可见细节；动效必须解释状态变化并支持 reduced motion。多页面或长期设计可维护 `PROJECT_ROOT/DESIGN.md` 保存稳定视觉契约，任务进度仍只写 `工作流程.md`，两者不混用。

严格原样迁移继续以源码/演示基线为准，不能用“品味提升”覆盖旧模板原貌；新设计仍服从当前框架、shadcn/ui + Tailwind CSS、Morphicons、业务行为锁和真实浏览器验收。
