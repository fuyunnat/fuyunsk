# fuyunsk：中文工程技能

这是按用户完整自定义指令组织的中文 `production-engineering` 技能，用于真实工程实现、修复、前端界面、代码审计、验证、Git 交付、数据库和部署。

**保留原文，不靠删规则提速。默认安装同时接好个性化短指令与本机技能：工程任务自动调用，普通聊天不加载工程正文。**

## 让 AI 自动安装（复制这段）

把下面这段发给**你电脑上的 Codex**。AI 应完成安装和个性化接入，不是只给教程或让你自己找目录：

```text
请在当前这台电脑安装或原位更新：
https://github.com/fuyunnat/fuyunsk

先读取仓库 main 的 README.md 和 docs/ai-installation.md，按同一提交完成安装。
本次授权你备份并更新本技能，以及个人全局指令中与本技能有关的自动调用部分。
必须同时完成：完整技能安装、个性化 / Codex 说明的短规则接入、旧规则冲突检查和验证。
使用 docs/personal-custom-instructions.md 与 global-AGENTS.example.md 的同一短模板，
填入真实安装路径，合并到当前生效的个人规则中；检查 CODEX_HOME 和 AGENTS.override.md。
保留我的其他指令和本机定制；同名技能只留一份有效安装，旧副本移到扫描目录外备份。
不要把完整工程规范塞回个性化，也不要要求我每次输入 $production-engineering。
不要更改 API Key、模型、MCP、插件、记忆、沙箱、审批或其他无关配置。
文件安装和自动调用要分别验证，不能只说“已启用”。每完成一个阶段给我简短进度。
遇到必须由我批准的权限或无法确认的冲突，只问那一个阻塞点；其他步骤由你完成。
最后用中文报告来源提交、安装路径、个人规则文件、备份位置、验证结果和剩余待办。
```

仅能访问 GitHub 的远端 AI 可以改仓库，不能假装已经安装到你的电脑。有本机文件权限时，AI 应直接完成配置；只有权限审批、无法自动刷新界面等必要步骤才交给你。

## 个性化怎样自动调用技能

```text
个性化 / Codex 说明中的短调度规则
    → 按工程目标自动调用本机 production-engineering
    → 读取 SKILL.md
    → 按当前领域和阶段读取原始规范条款
```

不要求你每次手写技能名。个性化短块负责调用，技能保留完整规则；**只安装技能文件、不接入短规则，不算完成本仓库的默认安装流程。** 用户明确要求不改个性化时除外。

桌面个性化与个人 `AGENTS.md` 是同一配置链路，不要当成两个独立地方各塞一整份规则。默认位置是 `~/.codex/AGENTS.md`，自定义 `CODEX_HOME` 或覆盖文件按[安装教程](docs/ai-installation.md)核实；[个性化模板](docs/personal-custom-instructions.md)由 AI 填入实际路径后合并，保护其他原有指令。

## 使用方法

直接描述工程目标，例如“修一下这个页面的按钮，只改本地并验证”。需要明确点名或排查匹配时可写：

```text
$production-engineering 做一个后台配置页，沿用当前项目技术栈。
$production-engineering 检查这个仓库有没有漏洞，先不要改文件。
```

自动匹配取决于客户端与模型，不把静态测试通过当作所有真实请求均命中的保证。

## 项目根目录工作流程

这里的“根目录”是当前正在开发的目标项目根目录，不是 `CODEX_HOME`、`~/.codex/` 或 Skill 安装目录。多项目仓库按实际子项目定位；参考源码与目标工程分开时写在目标工程，不能改参考副本。

每次实现、修复、重构都由 AI 在**目标项目根目录 `工作流程.md`**维护同一份可见清单，小改也记必要几项。不是只在聊天里列计划，也不是把记录藏到技能目录或 `work/` 中。

```markdown
- [ ] W001【待做】待开始的具体事项。
- [ ] W002【进行中】正在处理的事项。
- [ ] W003【待验证】代码已写完，尚未验证。
- [x] W004【已完成】实际完成且验收通过；证据：可核对结果。
- [ ] W005【阻塞】写明失败或缺失条件，不能提前打勾。
```

接到新任务先追加事项，做完一项及时更新一项；新增需求继续追加，不删未完项和历史。换会话、上下文压缩或问进度时，先读当前任务区块，再核对真实文件。源码基线、改变项、保留项和下一步也放在该区块，不靠聊天记忆。

普通聊天不建文件；只读不写，除非明确单独授权清单。只维护少量增量文字，不因此新增后台服务、额外模型调用或每轮全仓扫描。清单不替代测试、旧任务快照或迁移台账，复杂任务只建立关联，避免三份独立待办。

见[工作清单规则](skills/production-engineering/references/workflow-checklist.md)和[空白模板](skills/production-engineering/templates/workflow.example.md)。本仓库根目录的[工作流程](工作流程.md)是自身维护历史，安装到别的项目时不能复制成它们的完成记录。

## 已提供源码：先读、按要求改，不擅自重做

用户已给源码，不等于还要用户从头描述一遍。技能先读取相关页面、样式、资源和行为实现，用实际路径/版本说明依据，区分本次改变项、必须保留项与验证方式；不把列过目录、读过 README 当作看过实现。

“保留原样，换一种框架或语言”只改变实现方式，不授权重新设计。用户明确目标优先于默认选型；HTML 改成 Vue 是示例，不是要求所有新项目改用 Vue。无相反明确要求的新设计仍默认 shadcn/ui + Tailwind CSS。保留原貌时复用源码中的布局、CSS、资源和交互，再做新旧对照；构建通过不等于外观一致。

源码能查明的先查；真实版本冲突、缺失资源、需求歧义在查证后仍影响结果时，只问具体阻塞点并暂停相关修改。不重复索要可访问的源码，不把“无法运行”说成“没有提供”，不以用户未回复默认批准。已明确且相容的要求直接执行，不额外制造确认轮次。关键决定随已有任务检查点恢复，不另起常驻服务或每轮全仓扫描。

本次优化是指令边界与读取路径修复。维护自检只证明规则文案、模板一致性和读取链路；不能保证模型实际逐次服从，也不能冒充已经对用户 HTML/Vue 页面做了视觉验收。

## 原始规范怎么保留

两份上传原稿分别固定为 `references/source-original.md` 和 `references/source-speed.md`；重构前仓库完整规范也未删除。`source-lock.json` 固定校验值；生成器按章节逐字节切片，顺序拼接必须与原稿完全相同。最后上传原文是执行基准，速度稿补充及冲突单独记录，不静默改变“必须”“禁止”和例外。

[逐段覆盖表](skills/production-engineering/references/rules-index.md)给出源行号和实际读取位置。[差异与采用说明](skills/production-engineering/references/source-policy.md)记录两版的通道、状态、Git 检查和授权差异。

## 核心要求

保留中文沟通和中文提交评审、八荣八耻、第一性原理检查、真实项目查证、用户改动保护、Git 门禁、可恢复删除、最小改动、职责分层、原有功能回归、API 兼容、数据库迁移、幂等、安全审计、证据和回滚要求。

前端不是只求能用：保留设计系统、布局、状态、响应式和视觉验收。**无相反明确要求的新设计统一 shadcn/ui + Tailwind CSS**，包括后台、配置页、用户端和独立页面；无宿主采用 React + Vite，语言沿用项目，未指定的新项目用 JavaScript / JSX。已有不兼容项目先确认迁移边界，不擅自整站换栈。

完整通道保留原文条件式任务分支推送和评审流程；只读、小改、不具备远端条件等按原文处理。**提交或推送不等于允许合并主线、强推、删除远端分支或操作生产。**

本次用户已明确更改前端选型：[当前前端规则](skills/production-engineering/references/frontend-stack.md)替代原稿的 Vue/Ant 默认，不是再加一套可选方案。原稿保留用于追溯，其他工程规范不变。

## 图标统一方案

图标统一通过 [Morphicons](https://www.morphicons.com/) 接入；它负责描边 SVG 的渲染与变形，图形数据仍可来自官网兼容的 Lucide、Tabler、Heroicons 等来源，不是只改一个依赖名称。React、Vue 和普通 JavaScript 按真实框架选择官方入口，不为图标迁移框架。完整边界见[前端选型中的图标规则](skills/production-engineering/references/frontend-stack.md#图标统一使用-morphicons)。

新设计与授权新增/替换的图标执行统一方案；原样迁移不擅自改变旧图标、样式或交互。不强制增加动画，明确处理减少动画偏好；找不到兼容图形或确实与保留要求冲突时，先查证再问，不偷换其他库。

AI 安装或升级技能时，同步更新前端规则和个性化短块中的 Morphicons 要求，但**不安装业务依赖**、不改当前业务项目、不另加后台服务。实际开发需要时才在目标业务项目接入，具体版本与许可证按对应来源核实。这里的规则检查不等于已在用户项目验证实际图标效果。

## 减少实际等待

已确定阶段与领域时，一次取齐原文和专项说明，不再强制串行经过入口、路由、索引、通道：

```bash
node "<技能目录>/scripts/read-rules.js" --stage 小改 --topic 内容
node "<技能目录>/scripts/read-rules.js" --stage 实现 --topic 前端,接口
node "<技能目录>/scripts/read-rules.js" --stage 只读 --topic 审计
```

这只是批量读取，不自动选择权限或执行命令；小改必须满足原文快速条件。验证、提交、推送等后续阶段只取当前所需；新任务从中途开始时追加 `--topic 通用,适用方式`。没有 Node.js 时用批量文件读取，不为此安装依赖。具体实现与对照办法见[运行延迟说明](docs/runtime-latency.md)。

减少工具往返不等于保证模型更快：较大的同批输入也可能增加模型处理时间，需测完整任务。已在上下文且未变的规则不重读；必要的验证、状态记录和授权不删。只合并独立检查，有依赖或共享写入的步骤保持顺序。

## 速度从哪里来

初始匹配只需要简短名称与描述；选中技能后读取短入口。原文已在维护阶段拆好，运行时只读当前领域和阶段的片段，不启动生成器、不联网拉规则、不默认恢复任务、不反复扫描或运行相同检查。完整任务仍须覆盖所有适用条款。

[只读条款助手](skills/production-engineering/scripts/read-rules.js)是可选工具，无第三方依赖；也可以直接用文件工具读取切片。文件体积和本地读取基准不等于模型端到端速度，实际改善需要在同一环境对照测量。

## 安装和升级

[安装教程](docs/ai-installation.md)是给 AI 执行的完整流程，覆盖固定版本下载、原位安装、备份去重、个性化接入、覆盖规则处理和新会话验收。[短全局模板](global-AGENTS.example.md)与[个性化模板](docs/personal-custom-instructions.md)内容相同，只合并一个标记块，不重复追加。

安装完成不等于自动调用已验证。AI 必须区分文件、界面和新会话的实际证据；不能仅凭自己的回答判定成功。更新 GitHub 不会自动更新你本机的技能或个性化。

## 整项目换语言与防遗漏

整项目重写、换开发语言或全量架构迁移使用[迁移专项](skills/production-engineering/references/project-migration.md)，普通小改不加载。AI 先固定旧版并盘点页面、接口、权限、任务、回调、数据和部署入口，再建立“旧能力 → 新实现 → 必需用例 → 执行证据”的对照。

实际迁移时，按模板建立盘点基线和迁移台账，绑定到任务状态。`check` / `finalize` 会核对每个旧功能、对应验收、代码指纹、恢复演练和阻塞；缺项不能靠一次普通命令成功宣布完成。保留旧实现只算阶段性共存，废弃必须有批准证据；生产切换另行授权。

```text
把这个项目从当前语言迁移到目标语言，业务行为保持兼容。
先盘点旧功能、确认边界与目标版本，建立迁移台账并绑定任务状态。
分模块验证，保留旧实现；中断后从记录恢复，不直接删除旧项目或切换生产。
```

台账模板和检查程序随技能完整安装；无敏感的迁移文档是否入库按项目约定，不能只放在不可同步的聊天里。代码、权限、数据库和前端 shadcn/ui + Tailwind CSS 要求继续适用。工具只检查已登记范围与凭据，不保证盘点绝无遗漏或模型永不遗忘。

## 验证（仅维护本技能）

日常使用本技能修改其他项目时，运行那个项目的测试与验收，不运行这里的生成器、自检或测速。修改本仓库、生成规则或检查安装完整性时，运行：

```bash
node scripts/validate-skill.js
git diff --check
```

主自检已包含 `build-rules.js --check`，无需重复执行；只排查切片一致性时才单独运行该命令。含新增文件的提交还要检查已暂存差异。测速是可选维护任务：`node scripts/benchmark-rule-loading.js --runs 7`，不属于日常业务流程。

校验包含原稿锁定、逐段重建、主题读取、中文入口、路径与错误处理、状态助手、秘密与产物检查。程序测试不代表真实 Codex 行为测试；安装后的触发、中文交付和实际耗时需按教程另行验收。
