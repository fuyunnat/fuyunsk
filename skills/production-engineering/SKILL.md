# 生产级工程

默认中文沟通和交付；命令、路径、协议字段、程序标识和分支名不翻译，项目明确要求其他语言时按原文例外。

## 执行入口

工程任务可自动调用或点名 `$production-engineering`，不扩权。清单固定在当前聊天源文件夹的 `PROJECT_ROOT/工作流程.md`；小改也记、续作先读、漏项追加、验后打勾，未授权只读不写。见 `references/workflow-checklist.md`。

1. 先读用户提供的源码、入口、样式、资源和行为实现；列目录不算已读。明确“改变什么、保留什么、依据在哪”，不得忽略源码另造方案。
2. 能从源码查明的不反问；查证后仍影响结果的关键歧义，只暂停受影响修改并问具体阻塞点。已明确要求直接执行，不反复确认。
3. 判断模式与风险，按阶段批量读原文和专项；最新明确要求优先于默认选型，迁移不等于重新设计。写入前查项目规则、Git 差异、用户改动和恢复点；非 Git 先备份。
4. 所有写入先按 `references/project-write-boundary.md` 核对根身份、真实目标和工作目录；越界停止。沿用分层，对照源码验证原貌与行为，构建成功不能代替验收。

有 Node.js 时批量读取：`node <技能目录>/scripts/read-rules.js --stage 实现 --topic 前端,接口`。阶段：只读、小改、实现、验证、提交、推送、评审、回滚。阶段只决定读取内容，不扩大授权；新任务中途开始追加 `--topic 通用,适用方式`，输出截断必须续读。

无 Node.js 时按上表和 `references/routing.md` 批量读文件，不装依赖、不跑生成器；未知条款查 `references/rules-index.md`。

## 不能被提速削弱的要求

- 原文优先级、八荣八耻、第一性原理和最小改动原则仍适用；通道不能把只读变成实现或扩大授权。
- 不覆盖、回滚或混入用户已有改动，不顺手重构、全仓格式化或迁移技术栈。业务解耦按“变化原因”和职责边界拆分：同一功能闭环高内聚；不同业务概念、生命周期、数据来源和权限边界分离。300/400/600 行和函数 80 行仅作风险信号。
- 删除进入回收站或可恢复备份；无法安全处理先确认。保护密钥、隐私、日志和数据。
- UI 是一级验收：源码迁移保留原貌与交互；新设计默认 shadcn/ui + Tailwind CSS，指定 Vue 等框架时按 `frontend-stack.md` 适配；图标统一 Morphicons。单一 `production-engineering` 已内置设计、反模板和浏览器验收工作流，不依赖额外 UI Skill。
- API、旧数据、配置、权限和原流程默认兼容。数据库、生产、支付、权限、密钥、部署等高风险写入先说明影响、证据和回滚，并取得确认。
- 完整通道保留条件式任务分支推送与评审；不默认授权主线、合并、强推、远端删除或设置变更。
- 不能靠删测试、弱化断言、无限重试或伪造证据制造完成；报告区分通过、失败、未配置、无法执行和未验证。

## 读取与速度边界

原文按字节切片，不以摘要替代；`source-original.md` 为原稿基准，用户当前明确要求优先。其他原稿与历史规范保留在 `references/source-policy.md`，不暗改冲突规则。

只加载当前阶段需要的章节，不预读全目录，不因新对话自动恢复任务，不重复检查、不为同一任务反复建分支或写状态日记。长条款须读完；外部方法仅按需补充，不能覆盖原规范。

独立只读检查可合并或并行；共享写入和依赖步骤顺序执行。改动后重验，不冒用旧结果。业务任务跑业务项目测试，不运行本技能生成器或自检；逐项更新工作清单并报告真实进度。

最终用中文报告改动、依据、保留项验证、交付状态、未完成项、风险和最小回滚方式。
