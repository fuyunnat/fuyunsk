# 生产级工程

默认中文沟通、提交、评审和交付；项目明确要求其他语言时按原文例外。命令、路径、协议字段、程序标识和分支名不翻译。

## 执行入口

工程目标可自动调用，也可点名 `$production-engineering`，均不扩大写入授权；普通聊天不启动工程流程。

1. 先读用户提供的源码及相关入口、样式、资源和行为实现；列目录不算已读。按最新要求明确“改变什么、保留什么、依据在哪”；不得忽略现成依据另造方案。
2. 能从源码查明的不反问；查证后仍有影响结果的关键歧义，暂停受影响修改，只问具体阻塞点。已明确要求直接执行，不反复确认，不把未回复当同意。
3. 判断模式与风险，按阶段批量读原文和专项；当前明确要求优先于默认选型，迁移不等于重新设计。写入前查项目规则、Git 差异、用户改动及恢复点；非 Git 先备份。
4. 限定改动、沿用分层；逐项对照源码基线验证保留项，不以构建成功代替原貌和行为验收；无证据不报通过。

有 Node.js 时一次取齐：`node <技能目录>/scripts/read-rules.js --stage 实现 --topic 前端,接口`。阶段：只读、小改、实现、验证、提交、推送、评审、回滚；小改必须先满足原文快速条件，实现对应完整通道，阶段不扩大授权。后续阶段假定已开始任务；新任务中途开始追加 `--topic 通用,适用方式`。未知领域才查 `references/routing.md`。输出截断必须续读，不能算读完。

无 Node.js 时批量读文件，不安装依赖或运行生成器；未知条款才查 `references/rules-index.md`。

## 不能被提速削弱的要求

- 原文优先级、八荣八耻、第一性原理校验和最小改动原则仍然适用。通道只决定检查深度，不能把只读变成实现，也不能扩大授权。
- 不覆盖、回滚或混入用户已有改动，不顺手重构、全仓格式化或迁移技术栈。不同职责应拆分，高内聚闭环不机械按行数拆分；保留 300/400/600 行、函数 80 行等原文评估信号。
- 删除进入回收站或可恢复备份；无法安全处理先确认，禁止以清理临时文件为由永久删除。保护密钥、隐私、日志和数据。
- UI 也是验收要求：源码迁移保留原貌与交互，默认栈不能覆盖用户指定框架；仅无相反要求的新设计用 shadcn/ui + Tailwind CSS，无宿主用 React + Vite；图标统一 Morphicons，原样迁移不擅换，详见 `references/frontend-stack.md`。
- API、旧数据、配置、权限与原有流程默认兼容。数据库、生产、支付、权限、密钥、部署和其他高风险写入先说明影响、证据与回滚，并取得确认。
- 完整通道保留原文条件式任务分支推送与评审，不一律禁止远端，也不默认授权主线、合并、强推、远端删除或设置变更。
- 不能靠删测试、弱化断言、无限重试或伪造证据制造完成。报告区分通过、失败、未配置、无法执行和未验证。

## 读取与速度边界

原文按字节切片，不以摘要替代；`source-original.md` 为原稿基准，用户当前明确要求优先。其他原稿与历史规范保留，差异见 `references/source-policy.md`；不暗改冲突规则。

只加载当前阶段需要的章节，不预读全目录，不因新对话自动恢复任务，不重复同一检查、不为同一任务反复建分支或写状态日记。需要读取的长条款分段读完，不能因长度预算而丢弃要求。外部方法仅按需补充，不能覆盖原规范。

独立只读检查尽量合并或并行，记录各项退出状态；共用写入目标、有先后依赖的步骤不能并行。修改后重新验证当前差异，不复用旧成功结果。业务任务跑业务项目测试，不运行本技能生成器或自检。报告实际进度，不另起模型调用。

用中文报告改动、依据、保留项验证、交付状态、未完成项、风险和最小回滚方式。
