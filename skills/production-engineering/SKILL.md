# 生产级工程

默认中文沟通。提交标题与正文、评审请求标题与描述、报告和面向用户的说明使用中文；项目明确要求其他语言时遵守原文例外。命令、路径、协议字段、程序标识和分支名保持技术原样。

## 执行入口

用户直接说工程目标即可，不要求每次手写技能名。点名 `$production-engineering` 也可调用，不代表授权写入。普通聊天不启动工程流程。

1. 判断只读、实现、审计或高风险模式，明确验收；技术问题自行查证，不逐项反问。
2. 按阶段与领域批量读取**原文及专项说明**，不串行重读入口、路由、索引、通道；上下文中未变内容复用，路径相对本技能。
3. 写入前查真实项目、最近 `AGENTS.md`、Git 差异、用户改动及恢复点；非 Git 先备份，不猜接口、配置、表或命令。
4. 限定改动、沿用分层、保护旧行为；验证当前差异及受影响旧流程后交付，不虚报正常。

| 当前步骤 | 必须读取的原文或专项说明 |
| --- | --- |
| 所有工程任务开始 | `references/rules/00-00.md`、`references/rules/01-00.md`、`references/rules/02-01.md` |
| 明确局部、可恢复、无外部副作用的小改 | `references/rules/00-01.md`、`references/rules/03-00.md`；验证按原文第二十章裁剪 |

| 前端页面或后台界面 | `references/frontend-stack.md` 的新选型 + 原文第九章 + 前端质量说明 |
| 后端、接口、性能、数据库、并发、配置、依赖、安全、日志 | `references/routing.md` 中对应原文章节，不遗漏命中的领域 |

有 Node.js 时一次取齐：`node <技能目录>/scripts/read-rules.js --stage 实现 --topic 前端,接口`。阶段：只读、小改、实现、验证、提交、推送、评审、回滚；小改必须先满足原文快速条件，实现对应完整通道，阶段不扩大授权。后续阶段假定已开始任务；新任务中途开始追加 `--topic 通用,适用方式`。未知领域才查 `references/routing.md`。输出截断必须续读，不能算读完。

无 Node.js 时批量读文件，不安装依赖或运行生成器；未知条款才查 `references/rules-index.md`。

## 不能被提速削弱的要求

- 原文优先级、八荣八耻、第一性原理校验和最小改动原则仍然适用。通道只决定检查深度，不能把只读变成实现，也不能扩大授权。
- 不覆盖、回滚或混入用户已有改动，不顺手重构、全仓格式化或迁移技术栈。不同职责应拆分，高内聚闭环不机械按行数拆分；保留 300/400/600 行、函数 80 行等原文评估信号。
- 删除进入回收站或可恢复备份；无法安全处理先确认，禁止以清理临时文件为由永久删除。保护密钥、隐私、日志和数据。
- UI 是交付要求，不只是功能能用；新建所有页面统一 shadcn/ui + Tailwind CSS，无宿主用 React + Vite。`references/frontend-stack.md` 定向替代原文旧选型，已有不兼容项目先确认迁移，不擅自换栈。
- API、旧数据、配置、权限与原有流程默认兼容。数据库、生产、支付、权限、密钥、部署和其他高风险写入先说明影响、证据与回滚，并取得确认。
- 完整通道的普通工程交付保留原文条件式任务分支推送和评审流程；不简化为“所有远端一律禁止”，也不扩大为“默认允许主线写入”。主线、合并、强推、远端删除与设置变更守原文授权边界。
- 不能靠删测试、弱化断言、无限重试或伪造证据制造完成。报告区分通过、失败、未配置、无法执行和未验证。

## 读取与速度边界

原文拆分是逐字节切片，不是删减摘要；以最后上传的 `source-original.md` 为基准；最新用户明确修改的前端选型优先。另一份原稿与重构前完整规范原样保留，差异见 `references/source-policy.md`。存在冲突时不暗自重写规则。

只加载当前阶段需要的章节，不预读全目录，不因新对话自动恢复任务，不重复同一检查、不为同一任务反复建分支或写状态日记。需要读取的长条款分段读完，不能因长度预算而丢弃要求。外部方法仅按需补充，不能覆盖原规范。

独立只读检查尽量合并或并行，记录各项退出状态；共用写入目标、有先后依赖的步骤不能并行。修改后重新验证当前差异，不复用旧成功结果。业务任务跑业务项目测试，不运行本技能生成器或自检。报告实际进度，不另起模型调用。

用中文说明：改了什么、为何如此、如何验证、保存及主线状态、剩余风险和最小回滚方式。未完成项如实列出。
