# 执行通道与成本控制

通道以用户最后上传原文的零章为准。同批读取 `rules/00-00.md`、`rules/00-01.md`、`rules/00-02.md`、`rules/00-03.md`（阶段批量结果已含这些条款时不重读），不得另造一套“标准通道”来削弱完整通道要求。

## 快速通道

只有目标、局部影响、恢复方式、无外部副作用、无敏感影响、低验证成本和真实可确认边界全部满足时才使用。读取目标及最近上下文，保护用户修改和恢复点，完成最小修改与验证。不默认维护状态、创建分支或评审、运行全部 CI、做全量回归或视觉审计。发现共享、数据、安全、外部写入等升级条件立即转完整通道。

## 完整通道

未知影响、公共入口、共享模块、全局配置、数据库、鉴权、资金、外部副作用、依赖、提交推送评审部署、跨职责、失败异常、长任务及原文明确列出的要求，按完整通道处理。完整不等于读取所有不相关领域；必须覆盖所有适用条款，任务状态只在阶段边界更新。

## 只读与授权

理解、解释、诊断、规划、审计保持只读。通道和风险不能把只读请求变成写入。只读任务默认不写任何状态文件；确需持久交接时先说明与只读要求的冲突并取得对应授权，不能通过“项目外记录”绕开用户的禁止写入要求。

Git 交付遵守 `rules/04-00.md` 及当前阶段的第四章条款，保留完整通道条件式推送与评审，不重写成固定口令白名单。高风险、主线和生产写入仍需确认。出现无法消解的授权冲突，先只读说明而不是擅自放行。

## 提速方式

同次任务已读且未变的规则不重复读；多个领域共用条款只读一次。把独立只读检查合并成一次执行并保存证据，避免反复提问、扫描、验证和写日记。只输出适用项目；不通过减少真实验证、删除原文或反复重试实现表面加速。

## 减少等待而不减少验证

优先一次批量读取当前阶段及所有已知领域，不逐条等待模型继续选文件。未知领域再补查，不能省略命中条款，也不能把“已读取”当作“已执行”。独立只读检查可在同一次工具调用合并；确认无共享写入、数据污染或资源冲突时才并行。分别保留命令、退出码和结果；一个失败不能被后一个成功覆盖。

备份→修改→验证→提交、迁移→校验等依赖链保持顺序；同一文件、同一仓库写操作不并行。内容未变的规则可以复用，但代码、配置、环境或差异变化后，之前的测试证据必须重新核实。完整通道状态仍按原文在阶段边界维护，不逐次读取或每次小修写日记。

正常业务任务执行业务项目的测试，不运行本技能的 `build-rules.js`、`validate-skill.js` 或测速脚本；这些只用于技能维护与安装完整性检查。开始、发现关键证据、验证、交付时简短说明实际进度，不用空泛进度冒充提速。
