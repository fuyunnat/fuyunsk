# 真实测试与交付报告

这条规则适用于任何写入、修复、实现或交付任务。它是收尾格式，不替代项目自己的测试命令、浏览器验收、接口检查或数据库隔离验证。

QA（质量检查）按影响分级：快速小改只验证受影响的真实行为，在短卡留步骤、预期、结果和证据，不读完整QA专项、不加全套测试或独立复核；复杂、高风险和上线任务按 `qa-acceptance.md` 处理测试对应表、检查失败门禁、独立验收及专项标准。仅补既有有效记录不重开QA，见 `workflow-checklist.md`。

## 先做真实验收

1. 改完后优先在真实项目、真实运行入口或安全隔离环境里验证刚改的行为，使用与用户结果直接对应的步骤。
2. 按影响选择测试：项目测试、接口 smoke test、真实浏览器页面、关键状态和响应式、隔离数据库迁移、打包后启动或其他能观察实际结果的检查。
3. `build`、`typecheck`、`lint`、静态扫描和文件检查只能作为辅助证据，不能单独冒充业务行为已经测试。
4. 测试必须在最后一次修改后执行；旧结果不能冒充新版本结果。没有实际证据时，状态保留为“待验证”。
5. 纯文案、规则或文档改动没有业务运行入口时，做文件、读取链路和回归检查，并在报告里写“规则/文档验证”，不要把它说成业务功能已实测。

## 缺条件时怎么处理

如果缺账号、密钥、服务、测试数据、依赖、浏览器或权限等真实测试条件：

- 不说“测试通过”或“已经完成”；
- 明确列出缺少什么、为什么需要、目前已经做了哪些安全检查；
- 继续完成不依赖该条件的工作；
- 写清用户提供后要执行的具体步骤。

## 收尾固定报告

每次写入任务结束时都用大白话报告下面五项，没内容也不能省略。报告要短，先说结果：实际能不能用，是全部弄好、只好了一部分，还是仍没确认；明确指本机、测试网站或实际网站，不能把电脑上检查通过说成用户的网站已经好用。

每项通常一两句，优先说用户看得见的变化和亲手试出的结果。不能只报命令、检查数或提交号，也不能只说“已完成、已验证、已交付”让用户猜。专业术语可以用，但术语随口解释，例如“401，就是网站没认出你已经登录”；不只丢错误码、配置名或代码块。

```markdown
做了啥：改好了什么，现在能做什么。
没做完啥：还有哪里没好；有没有更新到用户实际使用的网站或软件。
怎么测的：在哪儿亲手点了、填了或运行了什么，看到了什么结果。
没测啥：哪一步还没实际试，为什么没试。
缺啥：确实要用户给什么；拿到后AI接着做什么。
```

没有就写“没有”；不适用就写“不涉及”。缺啥只写核实过、必须由用户提供的东西，如测试网址、账号或操作权限；不能编造缺口。AI能做的继续做，已有权限和工具可查到、改好、更新或测试的，不让小白自己猜设置或执行命令。确实需要用户操作时，只说在哪儿做、做什么、怎样算完成。

各专项的验证深度不变，技术证据（完整命令、结果、文件、版本、日志、风险和恢复办法）保存在 `工作流程.md` 或详细报告；用户回复统一并入这五项。只在用户要求或必须核对时补必要细节，并解释用途。

例子：修正了错误提示，但实际网站还没更新、缺网站更新权限和测试账号时，应这样说：

> 还没彻底修好，实际网站能否登录还没确认。
>
> 做了啥：修了“登录失败却显示成功”的提示。
> 没做完啥：修复还没更新到你的网站。
> 怎么测的：在电脑里打开页面，填了错误账号，确认会提示失败。
> 没测啥：还没在实际网站成功登录，因为没有测试账号。
> 缺啥：需要网站更新权限和一个测试账号；拿到后我会更新网站，再亲自登录确认。

例子中的事实必须来自本次真实工作，不能照抄成测试结论。只有真实验收证据成立后，清单事项才标记“已完成”。

## 已启用的项目知识归档

项目已启用知识归档且当前授权覆盖时，将值得长期保留的决定、使用方法、实测结论、未验限制和接手入口整理到已有知识文档，沿用项目约定的存储和工具。先读再更新原条目，引用已有证据，不复制整份清单或原始聊天；脱敏并排除凭据、个人信息。无新增长期信息时跳过，不为普通小改另建知识系统或重复上传。

未启用时不自动注册、安装或上传；不因归档反复追问，也不把某个项目的存储选择变成通用默认。只读、暂停或明确跳过时遵从。分别核对本地整理、上传与核验结果；上传成功不等于业务完成，归档失败不伪报通过，保留本地资料并在五项报告中说明实际卡点，不重开已通过的业务验收。

## 前端新增页面的额外验收

新增或修改前端页面时，还要在真实页面里检查布局是否合理、组件是否协调、颜色/字体/图标是否沿用项目规则，以及桌面和手机视口是否正常。页面里有输入框、表单、筛选、上传、按钮或弹窗时，AI 要用安全的测试值实际填写和操作，检查校验、加载、成功、失败和空状态；涉及真实提交、支付、发信或生产数据时改用隔离数据，缺少条件就列入“缺啥”和“没测啥”。只有截图或构建通过不能代替这些操作。

开发中持续预览见 `frontend-delivery-loop.md`，不等最终汇报才让用户看页面。前端汇报附实际可打开的网址、改动页面入口、数据来源及刷新方式；明确预览和正式网站的区别、哪些仍未验收。复用健康服务，不把小改升级成整套流程。
