# 真实测试与交付报告

这条规则适用于任何写入、修复、实现或交付任务。它是收尾格式，不替代项目自己的测试命令、浏览器验收、接口检查或数据库隔离验证。

## 先做真实验收

1. 改完后优先在真实项目、真实运行入口或安全隔离环境里验证刚改的行为，使用与用户结果直接对应的步骤。
2. 按影响选择测试：项目测试、接口 smoke test、真实浏览器页面、关键状态和响应式、隔离数据库迁移、打包后启动或其他能观察实际结果的检查。
3. `build`、`typecheck`、`lint`、静态扫描和文件检查只能作为辅助证据，不能单独冒充业务行为已经测试。
4. 测试必须在最后一次修改后执行；旧结果不能冒充新版本结果。没有实际证据时，状态保留为“待验证”。
5. 纯文案、规则或文档改动没有业务运行入口时，做文件、读取链路和回归检查，并在报告里写“规则/文档验证”，不要把它说成业务功能已实测。

## 缺条件时怎么处理

如果缺账号、密钥、服务、测试数据、依赖、浏览器或权限等真实测试条件：

- 不说“测试通过”或“已经完成”；
- 明确列出缺少什么、为什么需要、目前已经做了哪些安全检查；
- 继续完成不依赖该条件的工作；
- 写清用户提供后要执行的具体步骤。

## 收尾固定报告

每次写入任务结束时都用大白话报告下面五项，没内容也不能省略：

报告要短，先说结果，不贴长日志，不堆专业词；命令、路径和错误只在帮助用户核对时写。

```markdown
做了什么：改了哪些结果、文件或功能。
没做/卡在哪里：尚未完成、失败或被阻塞的事项。
怎么测的：实际命令或操作、测试环境和结果。
还没测什么：未执行的真实流程、状态、设备或场景，以及原因。
缺什么：需要用户提供的账号、服务、数据、依赖或权限；提供后怎么测。
```

没有未完成项写“没有”；没有适用的未测项写“未发现适用未测项”；没有缺条件写“没有”。只有真实验收证据成立后，清单事项才标记“已完成”。

## 前端新增页面的额外验收

新增或修改前端页面时，还要在真实页面里检查布局是否合理、组件是否协调、颜色/字体/图标是否沿用项目规则，以及桌面和手机视口是否正常。页面里有输入框、表单、筛选、上传、按钮或弹窗时，AI 要用安全的测试值实际填写和操作，检查校验、加载、成功、失败和空状态；涉及真实提交、支付、发信或生产数据时改用隔离数据，缺少条件就列入“缺什么”和“还没测什么”。只有截图或构建通过不能代替这些操作。
