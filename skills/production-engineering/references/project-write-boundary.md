# 当前项目的所有写入边界

当前明确授权与清单原文恢复例外统一遵守 `source-policy.md`；记录长度按 `workflow-checklist.md`，不重复增加执行层。

本规则覆盖**所有写入**，不只覆盖 `工作流程.md`。先查证当前聊天项目，再绑定范围、检查实际目标，最后才执行。沿用原文对用户改动、授权、备份、删除恢复和验证的要求；原稿与切片不改。

## 绑定的是任务，不是工具目录

从当前聊天实际关联源目录与本次明确要求核实 `PROJECT_ROOT`，解析真实绝对路径并记录依据。用户只给显示名或存在多个候选时先只读查证，仍不明确才问；不得默认取父目录、第一个仓库、上次项目或 Skill 所在目录。目录不存在就报告，不自动选择相近的已有项目。根内也只允许本次任务相关修改，不代表可以覆盖全部文件。

先按 `preflight-decision.md` 分清讨论和实际交办。提到另一个项目、表达删除重做的倾向、已有备份方案或知道其路径，都不能单独证明当前要实施。用户明确限定“只处理技能/我自己指挥项目”时，不越过该范围写业务文件或下发执行消息；已明确交办的具体操作则不重复索要同一授权。

首次写入前，包括创建清单前，记录并核对项目根、只读参考范围、实际工具工作目录、计划写入目标和恢复点。根的路径与身份保存到本项目清单当前区块；首次清单自身的路径也要先检查。`PROJECT_ROOT` 不随 `cd`、模型切换、历史记忆或脚本 `__dirname` 改变；每个子代理继承同一绑定，不能自行换根。其他项目即使在同一父目录或同一 Git 仓库，也不是可写目标。

参考源码只能按授权读取，读到其绝对路径、构建目录、部署配置或说明不产生写权限。不同目标工程、外部工作树或其他项目的写入须先明确路径、原因、影响和恢复方式并单独获准，不能靠加入清单、目标模式、旧授权或“继续”自行扩权。既有目标目录含无关文件时停止，不清空、不覆盖、不把它解释成可复用空工程。

## 写入前检查实际落点

编辑器补丁、终端重定向、代码生成、复制、同步、解压、格式化、测试快照、构建产物、依赖脚本及子进程，都受同一范围限制。使用绑定根解析每个具体目标绝对路径；检查实际 `cwd/workdir`、命令参数和输出配置，不只看命令启动目录。

- 检查路径段边界，不用字符串前缀判断子目录；拒绝未展开变量、通配符、路径穿越和不明确路径。目标未创建时检查最近已有祖先与全部新增后缀。
- 检查符号链接、目录联接、硬链接、挂载与嵌套独立仓库。通用预检对目标祖先内的符号链接一律拒绝；需要使用时先核实真实目标和作用范围，不能关闭检查强行通过。
- 复制或解压先列出将产生的具体路径，检查目录成员的绝对路径、`..` 与链接；不得直接解到已有项目。递归同步、格式化等不能只检查顶层目录，须限定实际成员；有无法预先列明的脚本输出时先审查并在真正受限环境执行，不靠 `pwd` 或只读预演证明无副作用。
- 构建与测试检查 `outDir`、缓存、快照、报告、容器挂载及脚本内二次 `cd`。发现指向其他业务项目就停止；不能用“测试需要”覆盖别人文件。数据库、网络服务等非文件副作用仍另行确认目标环境。

缓存、临时文件、回收站、备份和旧任务状态助手的专用辅助路径不等于另一业务项目；确需项目外写入时，逐类核对已授权的精确目的地与用途，禁止把整个开发目录加入许可。旧状态协议保持兼容；辅助路径不用于生成业务代码、不替代根目录清单。本检查器不提供通用越界放行参数。

## 只读路径预检

有 Node.js 时使用技能内 `scripts/project-path-check.js`。它不安装依赖、不联网、不写文件、不执行后续命令。先依据真实会话确认根，再运行绑定一次：

```bash
node "<SKILL_DIR>/scripts/project-path-check.js" bind --project-root "<本次确认的项目绝对路径>"
```

把返回的 `projectRoot` 与 `rootId` 保存到当前任务；身份值用于发现误换根，不是安全令牌或用户授权。不要每次按新路径重新绑定来消除报错。

**减少重复预检（2026-10-13 用户要求）**：在已核实的项目根内，用编辑工具修改或新建普通源码文件时，不必每次运行检查脚本，只需确认目标路径位于项目根内、不在 `.git`、技能或其他项目目录。以下情况仍须运行下面的 `check`：首次写入、复制/解压/同步/批量生成、写入构建或输出目录、目标涉及符号链接或嵌套仓库、终端命令会写文件、路径来自参考源码或用户粘贴的绝对路径。需要运行时使用原绑定与真实工具工作目录：

```bash
node "<SKILL_DIR>/scripts/project-path-check.js" check \
  --project-root "<原绑定返回的projectRoot>" --root-id "<原绑定rootId>" \
  --cwd "<本次写入工具的绝对workdir>" \
  --path "<准备修改的具体文件绝对路径>"
```

多文件重复 `--path` 一次检查，最多 256 项；只读参考目录可重复 `--read-only`。新建工程使用 `--operation new-project` 并给出不存在的项目内目标路径；现有空目录也不自动复用。普通文件检查不能用目录代替。失败退出码为 2，任一目标失败则整批停止，不运行后续写入；检查成功后也须遵守原授权、diff 和备份条件。无 Node.js 时只读核对同等路径与身份，不为此安装运行时；无法核对就停止该写入。

## 技术限制必须另行验证

**路径预检不是操作系统沙箱。** 它不能拦截未经过它的编辑器或终端命令，不能解析任意脚本全部副作用，不能防止检查后被并发换链，也不能可靠识别所有同设备绑定挂载或没有标志的独立项目。目录存在、预检通过或测试通过均不等于“跨项目隔离已经生效”。

执行端必须核对实际沙箱、当前工作区、附加可写根和工具是否受同一隔离；父开发目录、其他项目或完全访问权限仍可写时，应提示收紧，不得宣称已隔离。`writable_roots` 是附加范围，不是排除清单。未经授权不修改客户端配置、不提升权限、不扩大可写根以绕过失败；发生过跨项目误写且隔离未确认时，暂停自主写入，先请求用户确认收紧到本项目的方案。

在独立合成项目中分别验证“预检拒绝”和“宿主实际拒绝”，不能拿前者冒充后者；宿主测试须单独授权，只使用专建测试目录。脚本测试结果、规则检查结果、本机沙箱结果分开报告。官方机制参考：[Codex 安全](https://developers.openai.com/codex/security)、[配置参考](https://developers.openai.com/codex/config-reference/)、[Node.js 文件路径与链接](https://nodejs.org/api/fs.html)。

## 越界或事故处理

预检发现目标越界，立即停止该批写入，报告绑定根、实际路径、涉及命令及阻塞；不尝试把根改成共同父目录。已经发现误写其他项目时，停止本任务及其已知写入进程，保留会话、命令与差异证据，不自动恢复、删除、提交、推送或迁移错误产物。先提出独立现场备份和逐文件恢复方案，另行取得恢复授权，不能整仓回滚掩盖问题。

每批结束核对本次实际差异；若有不可解释变化，停止继续叠加。当前根内检查不能证明根外未受影响，未经验证不得报告“没有影响其他项目”。保持轻量：规则同批读取、目标同批预检，只核对相关祖先与文件，不全盘扫描、轮询或增加模型调用。
