# 项目工作进度面板

工程对话开始/继续并确认项目根时，自动检查面板；“打开进度面板”“可视化 AI 做到哪一步”“切换项目看流程”也读取本规则。面板只显示已记录的进度，不是 AI 内部实时状态，也不冒充已获取应用里的全部聊天。

## 一个数据源

每个实际项目保管自己的 `PROJECT_ROOT/工作流程.md`。同一实际项目的多个对话使用独立任务区块，稳定编号；可选加一行 `对话：修登录 / 调整页面`，不能猜未知对话 ID。不创建第二套任务 JSON、数据库或待办。记录格式、验收与停止仍按 workflow-checklist / bounded-completion，不因面板加新步骤。

面板按任务显示复选框和带 ID/状态的规划表，默认选择最新任务，可切换历史；当前项、下一步、阻塞、状态及清单更新时间直接来自文件。取消不算完成，编号冲突/勾选矛盾提示核实；计数仅代表已记录事项，不代表全项目功能覆盖或测试通过。

AI 实施时沿用短清单：开始标进行中，做完但未验标待验证，真实验收通过才勾选；仅在有进展、阻塞或当前项变化时更新。无需每个工具调用都写文件。用户禁止记录/要求原文恢复时仍按 source-policy 例外，面板不反向添加记录。

## 自动检查与守护

工程对话开始、继续或恢复时，核实当前 PROJECT_ROOT 后运行一次 `--ensure`；已有项目根与用户约束未变，不每次反问。健康面板复用；离线启动本机守护。此默认来自用户明确要求，不要求手写专业提示词。闲聊、概念问答、安装/升级阶段、项目归属未知时不启动；用户要求停用、禁止启动进程或禁止任何写入时服从。普通只读工程任务不写项目清单，面板仍只读已有文件。检查失败简短报告并继续独立业务，不把面板变成新门禁。

```bash
node <技能目录>/scripts/progress-panel-service.js --ensure --project "项目=/已核实的绝对路径"
```

默认从 `http://127.0.0.1:4318` 起选最多 20 个本机端口；复用同项目面板，不关闭占端口的其他服务。显式 `--port 4318` 被占用时报错，不换端口。用返回的真实 URL；不得把远程环境地址说成用户电脑已打开。多项目仍可逐个传 `--project`，只登记明确指定根，不扫描磁盘、全部聊天或导入别的项目。不同根集合不复用同一个守护；需要一个页面看多个项目时一次指定完整集合。

宿主会清理后台进程时，用相同 `--ensure` 命令加 `--foreground`，保留工具返回的执行会话；复用该会话，不每轮开一个。启动输出只证明当次探测，跨命令复查失败不能报持续在线；若宿主两种方式均不支持，报告限制，继续业务，不反复修复或安装系统服务。

守护每秒检查运行状态，面板子进程退出后退避重启，连续 3 次健康失败才处理自己创建的子进程；有限重试：60 秒内 5 次退出停止恢复，下一次工程对话再明确检查结果，不无限补丁。只重启面板，不启动业务服务、数据库或迁移，不安装系统守护、开机启动或部署公网。已有手动启动的健康面板先观察复用，确认端口已释放后再接续启动；不终止旧进程。旧进程失去响应但仍占端口时报告阻塞，不冒充已恢复。

用户说“停止面板”时仅停止当前项目的守护，并遵守其后续停用要求，不立即重启。若返回 panelStillRunning，表示原来的手动面板仍运行，需在原终端停止；不把停止守护说成已关闭旧面板。命令：

```bash
node <技能目录>/scripts/progress-panel-service.js --stop --project "项目=/已核实的绝对路径"
```

脚本仅在操作系统临时目录的当前用户私有子目录保存端口锁、PID、指定根与运行状态，不保存任务、聊天或清单内容，**不是第二套任务状态**。原 `progress-panel.js` 前台 CLI 保留。只需 Node.js 18 及以上标准库，无运行依赖；没有 Node.js 时报告面板不可用，继续业务，不安装无关依赖。

任务状态只读取指定根下的工作流程.md，清单不存在显示“尚未建立”，不自动创建。改动地图按下文只读该项目 Git，附件只读取清单明确登记的项目内证据；拒绝符号链接，浏览器不能传入任意路径，没有写入 API。禁止访问数据库、.env、上传或其他项目。面板的运行记录不写入业务项目，业务只读边界不变。

## 展示与限制

使用紧凑项目工作台：左侧直接列出项目和任务记录，可搜索任务/对话、筛选未完成任务；中间展示当前项、按清单顺序排列的流程和完整记录，流程按钮可跳转对应步骤；右侧集中展示目标、保留与边界、阻塞与待验证、证据及完成/停止条件。长记录和证据可展开，不用放大卡片铺满页面。窄屏改为单列，任务导航可展开。

元数据读取清单已有的 `目标：`、`保留：`、`验收与停止：`（也识别 `验收：`、`停止条件：`），证据读取事项描述中的 `证据：`。没有记录就明确显示缺失，不反推测试通过。流程表示清单顺序，不推断真实执行时间或依赖关系。

每 4 秒读取文件，页面隐藏时暂停轮询。默认跟随最新记录；手动选历史任务后，刷新保留选择，选回最新记录才继续跟随。AI 未更新清单时，显示最后文件更新时间；连接中断标明旧记录，不伪造实时推进。后续重新启动时用相同的已核实项目路径，进度仍来自同一文件，不需要导入聊天。

宿主是否能展示网页、用户本机是否已启动面板要分别验证。在远程执行环境运行不等于用户电脑已打开；报告真实运行位置、地址及限制。仅看面板不能证明验收完成，也不能保证 AI 每轮遵守记录规则。

## 改动地图、证据与快捷提示词

三项工具放在执行流程下的紧凑标签区，切换项目/任务会清除旧差异；接口迟到不得覆盖当前任务。无需用户写专业触发词。任务进度仍只有清单一个来源，Git 是独立比较证据，不是第二套任务状态。

技能升级后已有面板进程可能仍使用旧接口；`/api/health` 的 `features` 包含 `insights`、`evidence` 才表示新接口可用。仅在升级后缺能力时，确认当前项目守护归属，再使用同一组项目参数顺序 `--stop`、`--ensure` 重启面板；不能每轮重启。手动旧面板若仍占端口，应在其原终端停止，不强杀或关闭其他服务。工具模块未加载时保留原有进度并提示重启；接口缺失显示读取失败，不能冒充新功能可用。

- **改动地图**：只读已登记项目的 Git 元数据，显示前端/后端/配置/文档分类和新增/修改/删除，可点开只读文本差异，标明读取时间。打开任务或清单记录变化时读取，也可按“重新读取”刷新；不是每秒实时跟踪代码。没有任务基准时明确显示“项目未提交改动（未归属本轮）”，不能归因于 AI、当前对话或历史任务。历史任务有基准时也包括基准之后其他改动，不能冒充精确的任务文件集。
- **基准纪律**：开始实施前，将已经核实的完整仓库 HEAD 作为 `基准：完整提交 SHA` 写入本任务区块一次；已有基准保留，后续提交或恢复对话不重置。只读/禁止记录的任务不为面板写基准；缺记录不猜历史基准，不重开已完成任务。无效/缺失提交拒绝比较，不偷偷退回 HEAD。若用户禁止 Git 检查，服从，不为面板扩权。
- **Git 边界**：只运行本机只读命令，不 fetch、checkout、stage、commit、reset 或执行业务；禁用可执行 fsmonitor、外部 diff、textconv、hook 及已配置的 clean/smudge/process 文件转换器，关闭可选索引写锁和继承的 Git 目录覆盖。差异使用原始文本，不执行 LFS 等转换脚本。缺 Git、无仓库、根变化或外置工作树/对象库时显示不可用，其他工具继续可用；不安装依赖。敏感路径及符号链接不预览，文本中的常见凭证行隐藏；启发式隐藏不能保证发现所有秘密，不记录/分享凭证。文件列表最多 200 项、差异预览最多 64KB，截断明确标注。
- **验收证据**：按事项展示已记录状态及证据，没有证据明确说明，记录“已完成”也不反推测试通过。使用事项证据里明确登记的项目相对路径；仅同源打开已登记 PNG/JPEG/WebP（不超过 5MB）及 TXT/LOG（不超过 64KB），不接入外链、SVG、上传目录、秘密文件、符号链接或项目外路径。不自动截屏、跑测试或写日志，不因展示区额外制造验收材料。附件不存在、格式或边界不符时显示不可用；日志常见秘密行隐藏。
- **快捷提示词**：“完成后停止 / 本批收尾 / 只读检查 / 展示差异 / 暂停收尾”带当前项目、任务标题及最新清单目标、保留和验收；同一任务改目标也更新文字。只复制到剪贴板，用户粘贴到对应对话后才生效；不发送消息、不改文件、不停止进程。剪贴板失败就选中文本供手动复制，不能提示复制成功。“本批收尾”明确修改目标并停止旧审查；其他预设不自行缩减完整目标，均保留真实验证和数据库保护，不能从记录文本自行推导新增授权。

附件使用 Markdown 内联链接：在事项的 `证据：` 后，将 `[截图]` 与 `(work/check.png)` 紧接拼成链接，日志同理将 `[日志]` 与 `(work/test.log)` 紧接。路径是业务项目实际产物，不是本技能自带文件；已有真实证据才登记，不为了面板补造文件。
