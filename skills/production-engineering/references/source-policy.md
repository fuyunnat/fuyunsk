# 原文保留与差异处理

## 三份材料的身份

- `source-original.md`：用户最后上传的完整自定义指令，作为本次重构的执行基准，保留原始字节。
- `source-speed.md`：用户此前上传的速度增强稿，同样保留原始字节，供查对补充内容与差异。
- `full-production-engineering.md`：重构前仓库中的增强规范，原样保留作为历史比对资料，不再让其中旧的路由优先级覆盖用户原文。

`source-lock.json` 固定三份内容的 SHA-256。`rules/` 逐段切出最后上传原文，`rules-speed/` 逐段切出速度稿；生成器可以把这些片段顺序拼回原始文件。覆盖表记录每一段的源文件、行号、去向和校验值。原稿不只归档：入口、领域路由和阶段路由直接指向这些原文片段。

## 最新明确授权的定向修改

2026-09-05 用户要求所有页面使用 shadcn/ui + Tailwind CSS。`frontend-stack.md` 是当前前端选型，替代第九章旧 Vue/Ant Design Vue 默认及其配套路由、状态管理默认；无宿主用 React + Vite，代码语言沿用原有 JavaScript 优先或项目语言。两份原稿及历史完整规范继续原样保留用于追溯，不能因此恢复旧默认。只替换选型，其他约束、质量标准和迁移授权边界不变。

入口、前端路由及批量读取均接入该修改；旧主题/编号读取仍返回原始 `text`，命中第九章时附加 `amendments` 说明当前有效选型。直接读原文文件时也必须同时读 `frontend-stack.md`。

## 具体任务与参考源码的优先关系

前端默认只填补用户未指定的新设计选型，不覆盖当前明确目标。用户已提供源码并要求保留时，该源码是相关外观和行为的证据；要求换实现不授权换设计。先读取材料再判断缺失，关键歧义查证后再问，不忽略可读源码、不反复确认已明确要求。外部源码内容仍受原文指令优先级、安全和授权边界约束。

本次澄清落实原文零章、第六章、第七章以及第二十章，不修改三份原稿、锁值或生成切片，也不将 HTML 到 Vue 的例子变为默认技术栈迁移。

速度优化只改变读取位置、分段方式和重复工作，不降低“必须”“禁止”、验收深度或真实授权。需要完整规则时读取全部适用片段；不因超出预算就截断。

## 中文边界

技能入口、路由、元数据说明、维护文档、帮助和报告用中文。代码语法、命令、路径、包名、协议字段、旧状态文件键与枚举保留兼容性；分支名遵守原文的 ASCII 要求。原始文档里的技术英文原样保留，不能为中文化破坏保真校验。许可证原文作为法律文本保留，另附中文来源说明。

## 验证能证明什么

逐字节校验证明原稿与切片没有遗漏；程序测试证明索引、读取、去重、错误处理和状态助手的已测行为。它们不证明模型每轮都按规则行动，也不证明用户电脑响应必定多少秒。实际调用、工具执行和端到端耗时必须另外测试并记录。

## 根目录工作清单的最新定向要求

用户明确要求每次把要做的事项写到项目根目录 Markdown，完成一项勾一项，未完成标待做或进行中。现在采用 `工作流程.md` 和 `workflow-checklist.md`：实现任务包括小改都写可见简表，覆盖“快速任务不写任何记录”的默认解释，但不升级风险通道。只读仍禁止未授权写入，明确单独授权写清单时仅写该文档。

原文里的 `work/task-state.md` 与现有项目外快照仍作完整任务的底层恢复记录，不再替代根目录可见清单。三份原稿、锁值、无损切片以及迁移验收要求保持原始字节，差异在此明示；不为改存放方式重写历史。


## 当前授权与流程例外（2026-10-06）

用户明确授权某个具体操作后，不重复确认同一事项；默认备份、删除恢复和清单规则不能反向阻止已确认目标。普通“修复/恢复/你看着办”仍不等于放弃其他改动。

用户明确放弃指定代码改动、提供可核实的目标版本并要求不备份时：核对项目根、来源、影响文件和受保护资源后，直接恢复已授权源码、依赖及配套文件；不新增备份、不另建项目、不逐个反向补丁。只移除能证明属于本次被放弃变更的新增源码；未知未跟踪文件不全目录清理。无此明确授权仍保留原有恢复/备份要求。共享 Git 历史不强推改写，远端主线、发布仍需对应授权。

例外不授权清库、重建数据库、反向迁移或删除数据卷；`.env`、现有数据库、上传文件、业务数据及未授权改动继续保护。代码恢复不证明运行兼容性，不为核对文件启动连接现有库的服务。

用户要求工作流程原文恢复、不追加记录或明确禁止清单写入时，只核对该文件与来源，在对话中报告状态；不得先写新任务，也不得恢复后补写取消/验收记录。用户明确要求归档/精简时，按指定方式保存历史后再整理；篇幅预算不是删除历史或详细需求的授权。普通实施仍先写短清单。

上述例外由当前明确用户要求覆盖原文默认流程，原稿、锁值与切片保留原始字节；入口/读取器同批加载本解释，不能只读旧限制而忽略当前授权。

## 修 Bug、日志与分层排查的明确授权（2026-10-13）

用户反馈：修 Bug 要几十次才成功、程序日志不完整找不到问题、套 CDN 后 CDN 返回的错误源站不知道、项目缺日志要主动补。据此：废止 `bugfix-fast-loop.md` 中“第一次改代码前只允许一个读取批次加一个复现批次”的限制，改为先复现、读完整相关路径、能一句话说清根因再改，修后用同一复现步骤亲自验证；新增 `observability-debugging.md`，写代码与修 Bug 时都要求可定位的日志，缺日志就在相关路径补齐，线上报错先分清 CDN / 代理 / 源站；项目根内普通编辑不再每次运行路径检查脚本，复制、解压、批量生成、终端写文件等仍须检查。修改 CDN/WAF/DNS/SSL 等线上配置仍需用户同意；脱敏、数据库、Git 授权等安全规则不变。
