
### 5. 提交前检查

每次提交前必须确认：

```bash
git status --short
git diff
git diff --cached
git diff --cached --check
git diff --cached --summary
git ls-files -o --exclude-standard
```

提交身份、钩子和远端检查：

- 必须读取当前仓库生效的 `user.name` 和 `user.email`；缺失时说明问题并等待用户配置，禁止编造身份或擅自修改全局 Git 配置。
- 仓库要求签名提交时必须沿用现有签名方案；签名不可用时明确说明，禁止伪造签名或静默降级。
- 禁止使用 `--no-verify` 绕过 pre-commit、commit-msg、pre-push 等钩子。钩子失败必须修复本次问题，或说明失败与本次改动无关。
- 推送前必须再次确认写入远端 URL、当前分支追踪关系和 PR 目标仓库。存在 `origin`、`upstream` 或 fork 时，必须区分“推送到哪个仓库”和“PR 合并到哪个仓库”，禁止推错远端。
- 必须检查 staged diff 是否出现意外文件权限、可执行位、符号链接、换行符或整文件重写；与需求无关的变化不得提交。

大文件和二进制文件检查：

- 提交前检查新增文件体积、二进制文件、压缩包、安装包、数据库备份、模型文件和媒体资源。
- 禁止把接近或超过 GitHub 单文件限制的大文件直接提交普通 Git 历史。
- 需要 Git LFS 时，必须先确认仓库已经使用 LFS，或向用户说明存储、带宽和迁移影响后再启用。
- 发布包、镜像、安装包等交付产物优先放 GitHub Releases、制品仓库或项目既有发布位置，不得默认塞进源码分支。

以下内容默认不得意外提交；如果仓库本来就明确跟踪、当前任务确实需要，并且已确认不含敏感数据，可以按项目规则提交，但必须说明原因：

- `.env`
- 密钥、token、密码
- 数据库文件
- 日志
- 缓存
- `node_modules`
- `dist`
- `build`
- `coverage`
- 临时文件
- IDE 配置
- 无关生成产物
- 调试代码
- 隐藏测试入口
- 后门逻辑

例外边界：

- 脱敏且仅包含占位符的 `.env.example`、`.env.template` 可以按项目规范提交，真实 `.env` 不得提交。
- `dist`、`build`、生成代码或共享 IDE 配置只有在仓库明确跟踪且交付流程需要时才允许提交。
- 测试数据库、fixture 或样例数据必须是合成数据，不得包含真实用户、生产数据或可还原的敏感信息。
