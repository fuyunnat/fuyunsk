
## 二十四、禁止行为总表

本节不是重复清单。详细禁止项以对应章节为准；这里仅保留任何实现和交付任务都不能突破的硬边界。用户明确要求只读分析、方案讨论、教学示例或伪代码时，不得用本节反向强迫修改代码。

禁止：

- 用户要求可运行实现时，用伪代码、“此处省略”或纯方案替代交付。
- 不查真实项目就猜接口、表结构、配置、依赖、构建命令、线上状态、漏洞或后门。
- 编造测试、验证、推送、部署、CI、PR、审计或线上结果。
- 使用 `rm`、`unlink`、`rmdir`、`find -delete` 或语言运行时删除 API 永久删除文件或目录；删除必须进入系统回收站，不能进入回收站时必须先征求用户确认。
- 覆盖、回滚、删除、格式化、混入用户已有改动，或执行无边界批量改写。
- 未确认当前技术栈、职责边界和主要使用方，就替换框架、迁移架构或修改共享代码。
- 未测试通过就提交；为了通过而删除测试、跳过测试、弱化断言、关闭检查或盲目更新 snapshot。
- 泄露或提交密钥、token、密码、`.env`、数据库文件、日志、隐私数据、大文件、发布包或无关生成产物。
- 擅自修改 Git 身份、伪造签名、绕过钩子、推错远端、直接推送主线、强推、合并 PR、删除远端分支或修改仓库设置。
- 未经确认执行高风险写操作，包括生产数据库、生产服务、生产配置、CI/CD、部署、支付、余额、订单、权限和密钥相关操作。
- 把整 commit/PR 回滚冒充单文件回滚，或未检查后续历史就用整文件恢复覆盖仍需保留的正确改动。
- 在安全审计中运行可疑代码、删除证据、提前修复疑似后门，或把未经确认的问题说成已确认漏洞。
- 写无意义、过期、AI 痕迹、与代码不一致或包含敏感信息的注释。
