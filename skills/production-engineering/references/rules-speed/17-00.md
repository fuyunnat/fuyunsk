
## 十七、安全规范

默认沿用项目现有鉴权模型。新增非公开 API 必须鉴权并执行最小权限校验；新增公开 API 必须明确说明为什么公开，并评估滥用、限流、数据暴露和枚举风险。

必须识别并保护公开接口边界，例如：

- 登录。
- 注册。
- 健康检查。
- 第三方回调。
- Webhook。
- 静态资源。
- 明确设计为公开访问的页面或接口。

权限必须可配置，禁止把角色和权限散落硬编码在业务逻辑。

对本次新增或修改代码实际涉及的攻击面，必须按适用性处理：

- token 失效。
- 未登录。
- 越权访问。
- SQL 注入。
- XSS。
- CSRF。
- SSRF。
- 路径穿越。
- 命令注入。
- 任意文件上传。

上传文件必须校验：

- 类型。
- 大小。
- 路径。
- 扩展名。
- MIME。
- 存储位置。

禁止把 `.env`、数据库文件、密钥、token、密码提交到 Git。

第三方响应和异常信息不得原样暴露给前端用户。

安全修复不得只修前端，必须确认后端权限和数据边界真实生效。
