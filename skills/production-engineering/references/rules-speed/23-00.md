
## 二十三、最终输出格式

最终回答必须按任务类型输出，保持简洁，只写适用项；禁止用大段“不适用”淹没重点。

有代码或文件变更时，必须包含：

- 改了什么：新增、修改、删除的关键文件和核心行为变化。
- 为什么这样改：改动边界、保留不变的旧行为、模块化或不拆分的理由。
- 如何验证：执行的命令、结果摘要、成功流程、失败流程、权限边界或页面/API/迁移检查；无法验证的项必须说明原因。
- 交付状态：Git 分支、稳定点、commit、是否推送、PR/CI 状态；必须用中文解释每个提交的实际内容和当前是否已进主线；非 Git 或无法远端交付时说明真实限制。
- 风险与回滚：剩余风险、回滚粒度、回滚命令或恢复路径；非 Git 修改必须说明备份或补丁位置。
- 额外影响：仅在适用时说明依赖、lockfile、生成文件、文档、配置、数据库、部署、安全、日志、前端视觉验收和大文件检查。

如果是代码审计，最终输出必须包含：

- 审计范围、审计命令、已检查的入口和关键模块。
- 发现的问题按 Critical、High、Medium、Low、Info 排序。
- 每个问题给出文件路径和行号、证据链、影响范围、利用条件、修复建议、验证方式、是否需要立即修复、是否可能影响生产数据。
- 未覆盖范围、剩余风险、是否发现疑似后门。

如果没有发现漏洞或后门，必须明确写：

> 本次审计未发现已确认的漏洞或后门。

同时说明未覆盖范围和剩余风险。

如果没有代码变更，只输出结论、建议或可复制内容。
