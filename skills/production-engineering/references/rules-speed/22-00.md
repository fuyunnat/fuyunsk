
## 二十二、完成定义 Definition of Done

一个任务只有满足所有“与当前任务适用”的条件，才算完成。不适用项应省略或标记为“不适用”，不得为了打勾制造无意义工作。

必须同时满足：

1. 需求闭环：实现或结论直接回应用户当前最新要求，没有擅自扩大范围，也没有把关键步骤推回给用户。
2. 改动可审计：改动边界清楚，只触碰必要文件；没有混入用户已有改动、无关格式化、无关重构、临时文件或计划外差异。
3. 职责清楚：代码落在项目真实职责边界内；页面、组件、服务、接口、数据库访问、配置和工具函数没有混杂成不可维护的大文件。
4. 安全边界成立：没有泄露密钥、token、密码、隐私数据或内部敏感信息；适用的输入校验、错误处理、鉴权、权限、日志脱敏已完成。
5. 兼容性成立：除非需求明确要求破坏性变更，否则已有入口、接口契约、默认值、排序、数据格式、权限和关键旧流程保持可用。
6. 场景规则已覆盖：涉及前端、后端、API、数据库、配置、依赖、部署、安全、并发或回滚时，已执行对应章节的适用规则。
7. 验证有证据：已运行当前环境可行且与风险匹配的 lint、typecheck、test、build、smoke test、页面检查、API 检查或迁移检查；“已测试”必须有命令、结果或可复现步骤。
8. 测试没有造假：不得通过删除测试、跳过测试、弱化断言、降低检查门槛、关闭规则或盲目更新 snapshot 来制造通过。
9. Git 交付真实：Git 仓库内的文件变更已按规则检查、精准提交；满足 GitHub 推送和 PR 条件时已推送任务分支并创建或更新 PR；不满足时必须明确说明原因。
10. 远端和高风险操作守边界：未经明确确认，不得直接推送主线、合并 PR、强推、删除远端分支、修改仓库设置、操作生产数据库、生产服务或生产配置。
11. 回滚路径明确：已说明当前任务适用的最小回滚方式；涉及数据库、配置或生产状态时，必须单独说明代码回滚之外的处理。
12. 结论诚实：所有无法验证、未完成项、环境限制和剩余风险已明确说明，不得把未知说成已确认。

非 Git 目录、非 GitHub 仓库、无远端权限、未配置 CI、用户明确要求不推送等情况，不等于本地工作失败；但不得声称完成了对应的 Git、GitHub、CI 或 PR 交付。

如果任何适用项不满足，必须在最终回答中明确列出未完成项和剩余风险。
