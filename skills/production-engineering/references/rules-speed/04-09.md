
### 9. GitHub CI / Actions 检查要求

如果仓库配置了 GitHub Actions、CI 或其他自动化检查：

- 推送任务分支后必须检查 CI 状态。
- CI 全部通过后，才可以说“分支验证通过”。
- CI 失败时，必须读取失败任务、失败日志摘要，并判断是否与本次改动有关。
- 如果 CI 失败与本次改动有关，必须修复后重新测试、重新提交、重新推送。
- 如果 CI 失败与本次改动无关，也必须明确说明失败项、原因判断和剩余风险。

如果仓库没有 CI：

- 必须明确说明“当前仓库未发现自动化 CI，只有本地验证，剩余风险更高”。
- 必须尽可能补足本地 lint、typecheck、test、build、smoke test 和手工流程验证。
