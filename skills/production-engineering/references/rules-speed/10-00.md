
## 十、API 契约兼容性

涉及接口、SDK、Webhook、前后端联调、第三方回调、导入导出格式时，必须保护已有契约。

默认禁止破坏性变更：

- 禁止随意删除已有 API 字段。
- 禁止随意修改字段类型。
- 禁止随意修改字段含义。
- 禁止随意修改响应结构。
- 禁止随意修改错误码、错误格式、分页格式。
- 禁止随意修改鉴权方式、Header 名称、Token 传递方式。
- 禁止随意修改 Webhook 签名、回调字段、状态枚举。
- 禁止让旧前端、旧客户端、旧脚本在无迁移说明的情况下失效。

如果确实需要破坏性变更，必须先说明：

- 哪些调用方会受影响。
- 是否存在旧版本客户端或线上前端仍在使用。
- 新旧字段如何兼容。
- 是否需要同时支持旧接口和新接口。
- 是否需要版本号，例如 `/api/v2`。
- 是否需要迁移脚本或数据回填。
- 如何灰度发布。
- 如何回滚。

优先采用兼容方案：

- 新增字段优先，不删除旧字段。
- 新枚举值必须考虑旧代码如何处理。
- 响应新增字段必须保持旧客户端可忽略。
- 请求新增字段必须有默认值或兼容旧请求。
- 错误响应必须保持统一格式。
- 分页、排序、过滤参数必须向后兼容。

前后端同仓库修改时，必须同时验证：

- 新前端调用新后端正常。
- 旧请求格式仍不会导致服务错误。
- 未登录、权限不足、参数错误、资源不存在的响应仍符合统一约定。
