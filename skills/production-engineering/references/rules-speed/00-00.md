
## 零、指令优先级与适用方式

执行前必须先判断哪些指令对当前任务真正适用。

指令优先级：

1. 平台、系统和开发者提供的更高优先级规则。
2. 用户当前最新、最明确的要求。
3. 当前文件路径范围内适用的 `AGENTS.md`、项目文档和仓库约定；存在多层 `AGENTS.md` 时，必须读取并遵守离目标文件最近且不与更高优先级指令冲突的规则。
4. 本规范中的默认规则。

适用原则：

- 本规范不能绕过平台权限、审批机制、沙箱限制或用户明确禁止的操作。
- 用户最新要求与本规范默认流程冲突时，在不违反更高优先级安全规则的前提下，以用户最新要求为准，并说明受影响的交付项。
- 只执行与当前任务相关的章节。标记为“不适用”的检查项不需要机械执行，也不应被写成失败。
- 简单、低风险任务使用最小必要流程；中高风险、跨模块或生产相关任务才展开完整检查。
- 同一要求在多个章节重复出现时，只执行一次并提供一份证据，禁止为了重复打勾重复运行相同命令、重复修改或重复汇报。
- 不得把清单逐项反问用户。应先从真实代码、配置、文档和运行状态中查证，只有仍然缺失且会实质影响实现、安全或验收的关键信息才提问。

任务模式：

- 只读模式：理解项目、解释、评审、诊断、规划、审计。允许读取和无副作用检查，禁止修改文件、Git、数据库、远端或线上状态。
- 实现模式：用户明确要求新增、修改、修复、重构或交付。允许在任务范围内编辑，并按风险执行验证和 Git 交付。
- 安全审计模式：默认只读；只有用户明确要求修复后，才进入实现模式。
- 高风险操作模式：可以先做只读调查、备份方案和风险评估；真正执行高风险写操作前必须获得明确授权。

通道选择：

通道用于决定执行轻重，不改变任务模式本身。执行前必须先判断任务通道，不能只看文件数量、任务字数或用户说“简单”；必须看影响范围、可逆性、外部副作用、数据/权限/资金/隐私/生产影响和验证成本。

判断是否属于“大改”，优先按下面标准：

1. 影响公共入口、共享模块、全局配置、路由、请求封装、权限链路、数据模型、部署、CI/CD、远端状态，直接算大改。
2. 需要改 2 个以上职责层，或同一功能同时动页面、接口、状态、持久化、配置，直接算大改。
3. 需要提交、推送、PR、合并、发布、部署、线上验证，默认按完整通道处理。
4. 需要写状态快照、回滚说明、验证证据或分支规划，通常说明任务已经不再是纯小改。
5. 如果 AI 不能从真实项目状态确认边界，一律按大改处理。
6. 只有目标明确、影响局部、可单提交回滚、无需外部副作用、无需长期续航时，才算小改。
