# 根目录工作流程清单

`工作流程.md` 是复杂或需续作任务清单；验收/停止见 `bounded-completion.md`，例外见 `source-policy.md`。快速小改只用对话内任务卡；复杂或需续作且根已知才按 `workflow-progress-panel.md` 打开面板。

## 写入门禁与例外

**快速小改例外（2026-10-13 用户要求）**：符合 `quick-core.md` 的快速小改不创建、不更新 `工作流程.md`，一句人话说明即可；已有当前任务清单的续作照常更新对应项。小改命中升级条件先补建清单再继续。**用户中途补充了第二件事，也视为升级**：立即建清单一起做完。

除快速小改外，凡本轮会写项目文件，默认先读/建/更新该清单并把首项标为“进行中”；门禁失败停止业务写入。用户要求只读、先讨论、不要改文件时不创建或更新；仅授权清单写入不能由此修改业务代码。普通聊天不创建清单。

## 什么时候必须写清单

按固定判断执行，不在“写/不写”之间凭感觉切换：

- **可以只用对话内任务卡**：单文件、一步、易撤回、马上可验证、无外部服务/账号/权限/数据库影响，且无继续或交接要求。
- **必须创建或更新 `工作流程.md`**：跨两个及以上文件/模块；两步以上实现或测试；涉及数据库、权限、登录、支付、部署、远端、依赖或外部服务；真实测试条件还没准备好；用户说继续/续作/交给另一个编辑器；已有清单；或用户要进度。
- **建了以后持续更新**：任务完成前不退回只在聊天记录；每项完成即更新，升级时在下一次业务写入前补建并迁入任务卡。
- **交接必须可独立继续**：当前区块写目标、已完成、未完成、当前动作、下一步、改动文件、测试命令与结果、未测试项、缺少条件、回滚点和用户决定。另一个编辑器只读清单和真实文件即可继续。

不建时任务卡写“单步小改，本轮不建 `工作流程.md`”；必须建时写触发原因，收尾可解释有无清单。

用户明确要求清单原文恢复、不追加记录或禁止清单写入时，按 source-policy 在对话中记必要状态，不得先写新任务；仍须核对项目根、写入范围与数据保护，不能扩大授权。

## 根目录绑定

从当前聊天所属项目关联的源文件夹查明正在开发的目标项目根目录。项目名称只是显示名；源文件夹不是工程内部名为 `src/` 的子目录。只查实际暴露的会话、工作区和文件。

绑定 `PROJECT_ROOT/工作流程.md`：不是 `CODEX_HOME`、`~/.codex/`、Skill/Codex目录。`SKILL_DIR`、`__dirname`、脚本位置只读规则；`PROJECT_ROOT` 不随 `cd` 改变，不能把任一业务项目根目录写死。真实工作树根目录只是定位线索，不能机械把上级 Git 根当作当前子项目根；每次写入核对绝对路径和工作目录。

多项目各自记录。同一实际项目的多个聊天用独立任务区块；多个源文件夹先查归属，不按第一个目录或显示名盲选。切项目重新核对绑定，不跨项目共用。用户明确指定独立目标才写在目标工程；新建子目录不自动把总清单移进去；原位迁移就写原项目根目录，参考源码目录默认只读。

根不明、同名文件、符号链接、写入冲突先查证，不能覆盖。已有清单先读再合并，保留用户说明和历史；不自动搬移删除，无写权限时报告实际阻塞，不能静默退回隐藏目录。错放先停止更新错处；其他项目条目不得带入，原文件不删除、不清空、不覆盖，报告旧路径、正确路径与处理结果。

## 一项一个当前状态

稳定编号；以下仅是状态格式：

```markdown
- [ ] W001【待做】具体事项与验收。
- [ ] W002【进行中】当前动作与下一步。
- [ ] W003【待验证】实现结束但未通过必要验证。
- [ ] W004【阻塞】原因与恢复条件。
- [x] W005【已完成】适用验收通过；证据：短摘要或路径。
- [ ] W006【已取消】用户明确取消；不计为完成。
- [ ] W007【本轮不做】退出本轮范围；保留以后处理，不计为完成。
```

先列必做事项和验收，做完立即更新该项，不能等全部做完才回填；验证通过才打勾。调研以事实证据验收，同一验证可共享证据。父项必须等适用子项均通过；未完成父项列子项 ID 和验收缺口。

进入下一个逻辑事项前核对目标、当前项和上一项进展已落到清单；缺失或过时先补记录再写业务代码。不需要每个工具调用写一次；只读/禁止记录例外不变。状态用标准标签；阶段、隔离验收和保留未提交等备注放描述，本轮不做不等于已取消。

默认推进一个逻辑事项；并行需独立工作区/负责人和单一协调。新任务独立编号，续作原位更新，不重置未完成项、不删失败和取消记录，不另写重复清单。源码或验收变化只重开证据失效的项目。

## 目标模式与动态追加

用户授权实施后自行拆解，不以用户没有预先审批整份清单为由等待；明确要求先确认方案或清单再动手时例外。缺清单时按真实源码与证据补建，保留正确成果，不重置任务，不凭聊天回忆补打勾。

新增需求继续追加：用户中途补充的立即记为必做项，一起做完；必要漏项按 bounded-completion 记录发现依据、对应目标、验收方式。新发现的必做事项也属于完成条件，但不能靠加入清单自行授权；非阻塞建议另记。关键歧义标阻塞，其他独立、明确且已授权事项继续。最终不只验收最初清单。

涉及候选审查时按 bounded-completion 固定审查分母与实施清单，当前摘要记录已分类/总数及剩余索引。完成一项同步当前项和下一步，不能顶部停在已完成项而底部继续新增。用户改目标原位记录最新目标与依据，退出旧范围保留为本轮不做/未覆盖，不重置已验成果或冒充旧父项完成。

原貌迁移要新旧页面对照、交互和响应式；后台要旧功能验收和真实后端联调。只登记适用项，截图或 build 不代替真实行为。

## 记录长度与续作

详细方案、字段/功能清单和已确认决定保留在任务段落或已有文件，摘要只写索引；小任务当前区块以 10 行以内为目标，普通多阶段当前摘要以 40 行以内为目标。预算只约束摘要，不删除或截断需求、失败证据或历史，不借压缩减少功能分母。不擅自建归档系统；授权归档后保存原文和索引。

每次继续、换会话、上下文压缩或问进度，先读根目录当前任务区块；不能只凭聊天回忆。当前目标未完不得报完成；历史或其他任务的未完项不阻塞本任务。

## 当前摘要一致性核对

续作/交付及最终答复前，核对当前目标、事项状态、当前动作/下一步、当前 HEAD和未验范围；任务基准保持不变。只有文件摘要不能证明实际 Git 或运行状态，未核实就明示；源码已提交不等于运行实例已更新。

已验项打勾、同步当前总状态；完成写“当前动作/下一步：无，本轮结束”，阻塞写未完ID、缺啥、恢复后的第一步，不能把未测项勾完成。更新真实Git/产物/运行结果，不残留已做完的“准备提交/再核对”。更新后重读当前区块，与最终汇报一致才答复。

同任务旧结论被后续结果取代时，当前摘要给历史快照索引与最新证据，不重新执行旧未完项。历史字节保留，不批量改写；不能借其他任务冒充通过。只读或禁止记录时仅在报告指出矛盾。

## 证据与交付

清单打勾不替代原 `check` / `finalize`。旧任务状态与迁移台账只关联路径，不维护三份互相独立的待办。修改清单后旧指纹失效时核实差异，不手填成功或排除文件绕过。仅文档进度变化核对原业务证据；不为写记录重跑全部业务测试。

清单随已授权改动精准交付，不为了隐藏它改 `.gitignore`。提交/推送事实发生后才回填，不能预先声明成功；允许一次文档回填，不为记录自身无限递归提交。
