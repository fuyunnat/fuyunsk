# 根目录工作流程清单

`工作流程.md` 是用户可见的唯一当前任务清单；位置/状态只在本文件定义，验收与停止见 `bounded-completion.md`，授权例外见 `source-policy.md`。小改也记，不因记录升级通道或自动运行状态助手。

## 写入门禁与例外

凡本轮会写项目文件，默认先读/建/更新该清单并把首项标为“进行中”；门禁失败停止业务写入。用户要求只读、先讨论、不要改文件时不创建或更新；仅授权清单写入不能由此修改业务代码。普通聊天不创建清单。

用户明确要求清单原文恢复、不追加记录或禁止清单写入时，按 source-policy 在对话中记必要状态，不得先写新任务或恢复后补记录。例外仍须核对项目根、实际写入范围与数据保护；不能拿例外扩大业务授权。

## 根目录绑定

从当前聊天所属项目关联的源文件夹查明正在开发的目标项目根目录。项目名称只是显示名；源文件夹不是工程内部名为 `src/` 的子目录。只查实际暴露的会话、工作区和文件，不假装读过未知设置。

绑定 `PROJECT_ROOT/工作流程.md`：不是 `CODEX_HOME`、`~/.codex/`、Skill/Codex目录。`SKILL_DIR`、`__dirname`、脚本位置只用于读规则，`PROJECT_ROOT` 不随 `cd` 改变，不能把任一业务项目根目录写死供其他聊天共用。真实工作树根目录只是定位线索，不能机械把上级 Git 根当作当前子项目根；每次写入核对绝对路径和工作目录。

多项目各自记录。同一实际项目的多个聊天用独立任务区块并协调写入；多个源文件夹先查归属，不按第一个目录或显示名盲选。切项目重新核对绑定，不跨项目共用。用户明确指定独立目标才写在目标工程；新建子目录不自动把总清单移进去；原位迁移就写原项目根目录，参考源码目录默认只读。

根不明、同名文件、符号链接、写入冲突先查证，不能覆盖。已有清单先读再合并，保留用户说明和历史；不自动搬移删除，无写权限时报告实际阻塞，不能静默退回隐藏目录。错放先停止更新错处，只合并核实归属且获准写入的本项目记录；其他项目条目不得带入，原文件不删除、不清空、不覆盖，报告旧路径、正确路径与处理结果。

## 一项一个当前状态

稳定编号；以下仅是状态格式：

```markdown
- [ ] W001【待做】具体事项与验收。
- [ ] W002【进行中】当前动作与下一步。
- [ ] W003【待验证】实现结束但未通过必要验证。
- [ ] W004【阻塞】原因与恢复条件。
- [x] W005【已完成】适用验收通过；证据：短摘要或路径。
- [ ] W006【已取消】用户明确取消；不计为完成。
```

先列必做事项和验收，做完立即更新该项，不能等全部做完才回填；验证通过才打勾。调研以事实证据验收。同一验证覆盖多项可共享证据，不重复执行。父项必须等适用子项均通过；未完成父项列子项 ID 和验收缺口。

默认推进一个逻辑事项；并行需工作区/负责人独立并单一协调。新任务独立编号，续作原位更新，不重置未完成项、不删失败和取消记录，不另写重复“本轮续作”清单。源码或验收变化只重开证据真正失效的项目。

## 目标模式与动态追加

用户授权实施后自行拆解，不以用户没有预先审批整份清单为由等待；明确要求先确认方案或清单再动手时例外。缺清单时按真实源码与证据补建，保留正确成果，不重置任务，不凭聊天回忆补打勾。

明确的新增需求继续追加；必要漏项按 bounded-completion 记录发现依据、对应目标、验收方式。新发现的必做事项也属于完成条件，但不能靠加入清单自行授权；非阻塞建议另记。关键歧义标阻塞，其他独立、明确且已授权事项继续。最终不只验收最初清单，也不能无限扩大完成条件。

原貌迁移要新旧页面对照、交互和响应式；后台要旧功能验收和真实后端联调。只登记适用项，截图或 build 不代替真实行为。

## 记录长度与续作

小改通常一到三项，当前区块以 10 行以内为目标；普通多阶段当前摘要以 40 行以内为目标，允许必要超出但说明用途。只留目标/保留边界、当前项、必要状态、阻塞、下一步和证据索引，不粘完整日志或反复复制规范。

详细方案、字段/功能清单和已确认决定保留在已有任务下的详细段落或已有文件，当前摘要只写索引。预算只约束活跃摘要，不删除或截断详细需求、失败证据或旧历史，不借压缩减少功能分母。不擅自新建归档系统；用户授权归档后保存可核对原文和索引。

每次继续、换会话、上下文压缩或问进度，先读根目录当前任务区块，再查相关差异和证据；不能只凭聊天回忆。历史只按需读，不每轮扫全文件。记录与事实冲突先核对再纠正。当前目标未完不得报整个任务完成；历史或其他任务的未完项不阻塞本任务。

## 证据与交付

清单打勾不替代原 `check` / `finalize`，不自动调用程序。旧任务状态与迁移台账只关联路径，不维护三份互相独立的待办。修改清单后旧指纹失效时核实差异，不手填成功或排除文件绕过。仅文档进度变化核对原业务证据仍适用，再查文档；不为写记录重跑全部业务测试，不无意义刷新时间戳。

清单随已授权改动精准交付，不为了隐藏它改 `.gitignore`。提交/推送事实发生后才回填，不能预先声明成功；允许一次文档回填，不为记录自身无限递归提交。原始模板不复制本技能维护历史，不写秘密或完整敏感日志。
