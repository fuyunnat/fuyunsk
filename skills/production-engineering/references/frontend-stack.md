# 当前前端选型：shadcn/ui + Tailwind CSS

## 当前任务优先：有源码先读，不把迁移当新设计

用户当前明确要求优先于本文件默认值；原文零章的指令优先级不变。“原样保留，只换框架/语言”是实现迁移，不是重新设计。新建组件文件、重建工程目录不改变这个任务性质；用户指定 Vue 等目标时按指定实现，不直接套 React 版 shadcn/ui 组件，也不擅自换成未经确认的社区移植，但**框架选择与视觉设计语言必须分开判断**：用户端原样迁移时以原源码和可复现运行效果为准；后台或其他允许重新设计的页面，如果用户没有另外指定视觉体系，Vue 等宿主框架不能被解释成“取消当前 Design System、允许自由套模板”。

用户已给源码时，先读取实际页面/模板、关联 CSS、主题变量、字体图片图标、交互脚本、状态和响应式断点；明确已读的路径及决定保留行为的依据。优先复用原 CSS 和资源，只适配框架必需的模板、状态、事件与构建；不得把源码只当灵感，再画一套“更现代”的页面。可审查后在安全本地环境运行原版建立对照；无法运行不等于没有源码，更不等于允许重新设计。

要求保留的布局、颜色、字体、间距、尺寸、文案、图片、交互、响应式和状态均为验收条件。迁移只改变被授权的实现方式；不得因“高质量 UI”“统一组件”修改保留项。源码存在多版或关键依赖确实缺失，先查路径与引用，再只问不能确定的基准；已有源码足以回答时不再索要截图或让用户重新描述。用户同时提出确实不能兼容的技术条件，说明冲突并等待选择，不能暗换框架或默认移植库。

以下 shadcn/ui + Tailwind CSS 规则仍是没有相反明确要求时的新设计默认，不撤销用户长期偏好，也不压过具体任务。

## 源码、演示站与实际运行效果共同作为证据

用户同时提供源码和可访问的演示站、测试站或旧系统时，不能二选一。当前最新明确要求优先；源码负责证明结构、样式、资源、状态和业务实现，演示站负责证明真实运行时的布局、交互、登录态、动态状态和页面关联。二者共同用于功能盘点与验收，不能只看源码静态结构，也不能只看截图或演示站表面效果。

当前环境具备浏览器、Computer Use、Playwright interactive 或等价网页操作能力，且用户已经授权使用演示账号时，应自行登录查看，不反复要求用户提供可由现有工具直接核对的截图。演示站默认只读：允许正常登录、导航、搜索、分页、展开等不改变业务状态的查看；删除、审核、支付、提现、发信、保存配置、提交表单等会改变远端状态的动作，必须另有明确授权。用户提供的演示账号、密码、token 等仅用于本次访问，不写入源码、Git、`工作流程.md`、任务快照、日志、截图文件名、配置模板或最终报告。

用户端原样迁移时，必须按同一页面、同一浏览器条件和可比测试状态对照原版与新版。源码与演示站出现差异，先判断是否来自版本、动态数据、登录状态、响应式或运行环境；仍无法消除且会影响实现时，只问具体冲突点。不能因为演示站暂时打不开、浏览器能力不可用或登录失败，就自行换一套 UI；对应视觉或交互只能标为待验证。

## 最新用户要求

用户在 2026-09-05 明确要求“页面都是用 shadcn/ui + tailwindcss 来写”。这是对原文第九章默认技术栈的定向修改，不是性能优化的附带删减。

新建前端页面、后台管理、配置页、用户端、独立工具和营销页面，且属于新设计、没有相反明确要求时，统一使用 **shadcn/ui + Tailwind CSS**。不再默认选择 Vue、Ant Design Vue、Pinia 或 Vue Router，也不另起第二套组件库。没有宿主项目时采用 React + Vite；已有兼容的 React 项目沿用其框架、构建、路由和目录，不因本规则强行换成 Vite。

原稿的 Vue 3 + Vite + Ant Design Vue 与普通 .vue/.js 选型、Pinia/Vue Router 默认值、仅后台适用的默认栈，以及 Ant Design Vue 的默认安装例外，不再作为无明确指定的新设计选型依据。代码语言仍沿用现有项目；无明确要求的新项目使用 JavaScript / JSX，shadcn 的 `components.json` 可设置 `tsx: false`，不因官方示例使用 TypeScript 就擅自转换项目。

## 框架选择与 Design System 分离

用户明确指定 Vue、Svelte 或其他非 React 框架时，框架要求优先，不能为了 shadcn/ui 把项目改成 React；但如果页面属于新设计、用户又没有指定另一套视觉体系，**不能把“不是 React”理解为“视觉规则失效”**。应继续继承当前 shadcn/ui + Tailwind CSS 的设计语言：统一主题 token、色彩、字体、间距、圆角、控件高度、状态、表格、表单、弹窗、导航、密度和交互层级，并用该宿主真实可维护的组件、Headless primitives 或已有基础组件实现。

官方 shadcn/ui React 组件不得直接塞进 `.vue`；也不能为了追求同名而自动安装 `shadcn-vue` 或其他社区移植。只有项目已经使用兼容实现，或用户明确要求并且兼容性、依赖和维护边界已核实时，才沿用或引入。否则保留用户指定框架，用 Tailwind CSS、语义 token 和宿主组件实现等价的设计契约，并如实说明使用的是“同一设计语言”，不能谎称使用了官方 React shadcn/ui 组件。

“后台自由设计”“你看着做”“自由发挥”等表述，只授权在既定需求与 Design System 内优化信息架构、布局、层级和交互，不授权删除旧功能、发明新业务、忽略参考源码，也不授权随意切换视觉体系。后台默认追求专业、克制、高信息密度和快速扫描；不得为了省时间套用传统深色大侧栏、浅色大背景、巨型统计 Card、浏览器式多标签页或组件库默认 Empty 拼成的通用 Admin 模板。

## 多页面后台先定代表页，再批量扩散

新建或大改多页面后台、管理台、运营台时，不能先批量铺完几十个页面再做视觉验收。先选择一个具有代表性的页面，建立颜色、字体、间距、圆角、控件高度、导航、表格、表单、弹窗、空状态和信息密度基线，并在真实运行页面中检查。代表页达到当前 Design System 与功能要求后，才把同一基线扩展到后续页面。

代表页未通过时，只暂停后台视觉样式的批量扩散；与其独立的后端、接口、数据层或用户端工作可以继续。已经完成的业务逻辑和接口不要因为视觉返工而推倒重写。若后续页面发现 Design System 需要调整，先修共享 token/组件契约和代表页，再按影响范围同步，禁止每页各自长成一套风格。

## 长任务边开发、边运行、边验证

完整前端重构、`/goal` 长任务或多页面开发，在环境安全且项目已有运行方式时，应尽量保持本项目开发服务常驻，优先利用 Vite HMR 或现有热更新能力。启动前检查已有进程和端口，不为每个文件重复启动一套服务；需要重启后端或前端时只处理本项目已确认的进程，不用无边界 `pkill`、`killall` 或类似方式。

服务成功启动后，向用户报告稳定的用户端、管理后台和 API 本地访问地址；除非端口冲突或配置确需变化，不无故更换。前端开发循环应包含：读取源码/参考站 → 实现 → 本地运行 → 浏览器实际查看 → 新旧或 Design System 对照 → 修正 → 响应式/状态检查 → 验证后更新任务清单和版本记录。构建成功、组件能渲染或单张新版截图都不能替代运行中的视觉与交互验收。

## 已有项目的边界

先核实真实框架、`components.json`、依赖、主题和组件目录。已有 shadcn/ui 页面复用当前组件；无相反明确要求的新建独立设计采用新选型。已明确授权的框架迁移按本次目标执行，不因创建新项目目录退回默认栈。已有非 React 项目或混用其他组件库的项目，先说明兼容或迁移影响并取得对应授权；不能静默退回旧默认，也不能把改技能规则当成已获整站迁移授权。不得把官方 shadcn/ui 的 React 组件直接塞进 `.vue`，也不擅自换成同名社区移植。

## 组件与样式

- 复用已安装的 shadcn/ui 组件和当前项目实际使用的底层实现；缺什么按需添加什么，不重新初始化项目、不整库下载、不覆盖已定制组件。
- 组件保持在已有 UI 基础层，页面负责组合，业务逻辑、请求、状态和校验按原职责分离，不把所有东西堆进 `.jsx` 或 `.tsx`。
- Tailwind CSS 用于布局、响应式和样式；色彩、圆角、间距、字体使用统一主题变量和语义标记。沿用现有 `cn`、变体及组件属性，避免重复类名、随机值、无边界全局覆盖。
- Tailwind、组件 API 与底层依赖按已安装版本核实；不混用不同大版本的初始化命令，不为样式小改升级依赖。
- 表格、表单、弹窗、抽屉、导航和状态组件优先复用；焦点、键盘、可访问性不能在自定义样式中丢失。

## 图标统一使用 Morphicons

所有新设计页面及明确要求新增、替换的界面图标，统一通过 [Morphicons 官网](https://www.morphicons.com/) 对应方案接入，包括导航、按钮、表格操作、表单、状态提示及组件内的箭头、勾选、关闭图标。不是仅在 README 写个链接，也不能保留新组件的另一套默认图标渲染就声称已经接入。

**先区分图标数据与渲染库。** 官网将 Morphicons 定义为描边 SVG 的渲染与变形方案，不是独立的全量图标素材库。官方包名是 `morphicons`；图形可来自官网示例采用的 Lucide、Tabler、Heroicons 等兼容数据，或项目已有且获得许可的描边路径。允许使用这些图形数据，不等于允许绕过 Morphicons 另起一套渲染方案。不得虚构 Morphicons 专属图标名称、包、CDN 或接口。

### 按实际项目接入，不改变用户指定框架

- React 使用 `morphicons/react` 的 `MorphIcon`；Vue 使用 `morphicons/vue` 的 `MorphIcon`；普通 JavaScript 按已安装版本使用 `morphicons/dom`。其他宿主先查对应官方入口，不为图标换框架、不把 React 组件塞进 Vue。
- `icon` 接收图形数据，不是组件实例。例如官方 Lucide 路径使用 `lucide` 的数据导出，不把 `lucide-react` 或 `lucide-vue-next` 的组件当数据传入。实际导出、宿主兼容条件及参数以锁文件、类型与对应版本官方文档为准。
- 先复用已有 Morphicons 接入与图形数据，缺失时才按业务项目的包管理器添加需要的依赖并更新锁文件。同类图标统一图形系列、尺寸、描边、颜色和对齐；接入 shadcn/ui 时保留按钮、焦点、ARIA 和状态逻辑，仅在授权范围替换图标渲染。不要全库导入、整库复制或为了图标重新初始化组件库。
- 不用 Emoji、临时手绘路径或未经同意的另一图标组件库顶替缺失图标。找不到合适图形、版本不兼容、资源或许可缺失时先查已有资料，再提出具体阻塞问题；不得假装已接入。品牌标识、复杂填充图形或要求原样保留的资源不能硬改成描边版本，无法同时满足时暂停该处并澄清。

### 原貌、可访问性与速度边界

- **原样迁移保留原图标与原交互。** 未明确要求更换时，不为统一库而改变形状、大小、布局或动效；可先评估以相同图形数据接入，无法等价保持就保留基线并询问冲突。当前更具体的保留要求优先，本条不授权全项目批量替换或重新设计。
- 统一用库不等于所有图标都要动画。只有真实状态切换需要且未违反保留要求时才变形，不自动循环、不阻塞点击。动效显式设置 `reducedMotion="user"` 尊重系统偏好；禁止动画或必须保持静态时使用已核实版本的 `reducedMotion="always"` 或等价静态方式，不能假定库默认尊重减少动画偏好。
- 图标按钮必须有可访问名称；装饰图标不重复朗读。验证键盘、焦点、主题、不同尺寸、减少动画和状态切换；涉及服务端渲染时检查初始 SVG 与客户端一致。构建通过不等于视觉或交互已经验收。
- 保留 Morphicons 及所用图形数据各自的许可证要求；不得把官网 MIT 标注理解为所有外部素材都采用相同许可。
- **安装技能不安装业务依赖。** 本仓库只保存规则，不把 `morphicons` 装进技能，不增加 MCP、后台服务或每轮联网取图。规则随现有前端批量读取一起返回；业务项目按需导入，静态图标不制造持续动画或额外模型调用。
