# 包裹式工作台界面

这是一套用于专业桌面工作台、运维控制台和管理后台的壳层与页面组合规则。它解决的是“内容区域被外层背景包裹”的空间关系，也规定包裹之后如何安排导航、页面内容、内层面板和底部信息。它不是给页面套一个大 Card，也不是营销页视觉模板。

## 适用范围和边界

当用户提到“包裹式 UI”“外框式工作台”“侧栏包住内容”“内容区有外层留白”“参考图里的工作台壳层”时读取本文件。它适用于共享页面壳层、侧栏展开/折叠、内容区圆角、底部产品信息栏和相关响应式调整。

不要因为一个局部面板有圆角就套用整套规则；也不要用本文件替换项目已有的颜色、字体、组件库、路由或状态管理。页面内层仍应遵循项目自己的 设计系统。本文件是框架中立的设计合同：React、Vue、Svelte、原生 HTML/CSS、桌面 WebView 或其他技术栈都可以实现同一空间模型。

## 参考图提炼：这类 UI 到底在表达什么

参考图展示的是三种可以共用同一壳层语言的页面，而不是三套互不相关的模板：

1. **多面板桌面工作台**：外层是安静的应用画布，左侧有工具/导航区，中间是主工作面，右侧是辅助面板，底部是独立的状态栏。多个面板可以并列，但它们共享同一套外框留白、间距和滚动边界。
2. **产品后台概览页**：侧栏从视口边缘连续到底，主工作区以白色或主题 surface 内嵌在画布中；模块头部、页签和概览面板在工作区内部按有限宽度对齐，底部信息栏不侵入主任务。
3. **设置与详情页**：工作区内部使用更窄的阅读/编辑列，标题、说明、值和操作形成稳定的行网格；细分隔线只表达内容分组，不被误认为侧栏或壳层分界线。

共同的视觉语法是：**外层留白制造包裹感，表面层级控制强调度，内容列控制阅读密度，边界只在有语义的位置出现**。不要照搬截图的品牌色、图标或具体文案。

## 核心空间模型

把页面视为四个协调区域，并在多面板工作台中允许工作区表面由多个同级面板组成：

1. **外层画布**：安静的背景，用来显出包裹关系，可以复用侧栏表面 token，也可以使用独立的 frame token。
2. **导航侧栏**：从顶部到底部的全高左侧锚点，品牌、主导航、账户/设置放在同一条连续表面上。
3. **工作区表面**：一个连续的内嵌表面，包含页面 页头 和路由内容；桌面端由它拥有圆角、边框和克制的阴影。
4. **底部信息栏**：位于工作区表面之外，与工作区左、右边缘对齐；需要时左侧放产品链接，右侧放版权、版本或归属信息。
5. **同级面板组（可选）**：在编辑器、监控台或 AI 工作台中，主工作面、检查器、日志和辅助对话可以是同级 同级表面；它们之间使用统一 面板间距，不要再包一层巨型卡片。

```text
viewport
└─ outer canvas
   ├─ navigation rail
   └─ shell column
      ├─ workspace surface(s) (header + route content / sibling panes)
      └─ information bar
```

包裹式的重点是四个区域之间的边界和对齐，而不是增加更多容器。页面 页头、表格、空状态和弹窗不应因为使用本模式就全部再套一层圆角卡片。

## 不可破坏的几何关系

用项目现有 spacing、radius、surface 和 border token 表达下面的关系。数值只是起点，不要脱离项目 token 硬编码：

| 关系 | 约束 |
| --- | --- |
| 内容左边缘 | 等于当前侧栏宽度 |
| 工作区顶部 | 留出一段可见的桌面外层留白 |
| 工作区右边缘 | 与视口右侧保持同等外层留白 |
| 工作区底部 | 在信息栏之前结束；底部圆角不延伸到信息栏 |
| 底部信息栏 左边缘 | 与工作区左边缘对齐 |
| 底部信息栏 右边缘 | 与工作区右边缘对齐 |
| 侧栏折叠 | 只改变侧栏宽度和对应内容 inset，不制造新间隙 |
| 同级面板间距 | 使用同一个 面板间距变量；不因面板数量改变外层 gutter |

桌面端可以从 8–12px 的紧凑 gutter 开始，工作区圆角可以从 8–12px 开始；最终以项目节奏和参考图比例为准。包裹关系必须能在展开和折叠两种状态下保持稳定。

## 表面层级、内容宽度和信息密度

包裹式 UI 的重点不是“所有东西都有白底”，而是让用户一眼分辨空间层级：

- **画布层**：最外层的安静背景，只负责显出工作区边缘，不承载主要操作。
- **导航层**：连续的导航表面，和 画布 有轻微对比即可；不要用多条线把品牌、主导航和账户区切成卡片。
- **工作区层**：承载当前路由或面板组的主要 surface，只在桌面端拥有一套统一的圆角、边框或克制阴影。
- **内部内容层**：页面内部按语义使用面板、表格、行分组或透明区；内层容器的强调度不能与 工作区层 竞争。
- **状态层**：hover、active、selected、loading、error 等状态优先通过现有 token、文字和图标表达，不靠随机高饱和色块。

根据任务选择内容列，而不是让所有页面都铺满工作区：

- **宽列**适合表格、时间线、监控和多栏编辑器；优先保持列稳定和横向扫描。
- **标准列**适合概览、列表和常规表单；页签、标题和主要面板共享同一内容边缘。
- **窄列**适合设置、权限和详情；标签、说明、值/操作按行对齐，留白用于分组而不是装饰。

内容列的最大宽度、左右内边距和栅格间距应来自项目 token 或布局组件；不要为每个路由随意增加不同的 `max-width`。当页面同时需要宽表格和窄说明时，可以让说明保持窄列、让表格在明确的宽列区域中横向滚动。

## 边界和分界线规则

- 侧栏从顶部到底部保持连续背景。品牌区下方不要默认加 `border-bottom`，设置/账户区上方不要默认加 `border-top`。
- 侧栏和工作区之间不要再叠加一条醒目的白色竖缝。用两个 surface 的对比和工作区自己的边缘表达层级。
- 工作区表面在 底部信息栏 之前结束；不能让工作区背景、边框或底部圆角继续延伸到 底部信息栏 后面。
- 页头 与路由内容之间的边框仍可以保留，因为它表达的是 页头 层级，不是侧栏分割线。
- 发现白线时先查源头：侧栏 `border-b`、侧栏底部 `border-t`、重复 `border-r`、1px gap 暴露了 body 背景、伪元素和 box-shadow；不要用背景色覆盖来“修掉”它。
- 同一边界只保留一种表达：边框、阴影或 surface 对比三者择一或组合到必要程度，避免双线。

区分两类边界，避免把页面内容规则误套到壳层：

| 边界类型 | 允许的表达 | 不应出现 |
| --- | --- | --- |
| **壳层边界** | 工作区 外缘的统一圆角、1px token border、克制阴影或 画布 对比 | 侧栏品牌/账户横线、重复竖缝、工作区背景延伸到 底部信息栏 |
| **内容边界** | 页头 与内容、设置 section、表格表头或行组之间的弱分隔 | 为了“看起来整齐”给每个内容块再加一圈圆角和阴影 |

如果使用多个同级面板，面板之间的 gap 本身就是边界；不要在 gap 两侧各加 border 再制造双线。拖拽调整大小的分隔条应只在 hover/focus/拖拽时提高对比，并提供键盘等价操作。

## 滚动、调整大小和状态稳定性

- 桌面端优先让 `app-frame` 锁定视口高度，让 工作区 的主滚动区负责垂直滚动；侧栏、页头 和信息栏保持稳定。确有长页面需求时，允许宿主项目采用页面滚动，但必须证明 底部信息栏 不漂移、圆角不裁切内容。
- 多面板的每个 滚动区域 都要设置 `min-width: 0` / 等价约束，避免长 URL、表格或代码把整个壳层撑出横向滚动；横向滚动应发生在拥有宽内容的面板内部。
- 面板 resize、折叠和恢复应以同一状态源驱动，设置最小/最大宽度并保留可见焦点；刷新或重新进入页面时是否记忆尺寸由产品需求决定，不要默默写入敏感或跨用户状态。
- loading、empty、error、forbidden、readonly 和 长内容 只替换内容区，不改变 侧栏宽度、壳层留白、工作区 圆角或 底部信息栏 对齐。
- 异步操作要在原位置给出进度、禁用重复提交和可恢复路径；不要用全屏遮罩把导航和壳层一起锁死，除非这是明确的阻塞性操作。
- 过渡只服务于展开/折叠、面板出现、状态切换等空间反馈；优先 transform/opacity 或宿主组件动效，尊重 reduced-motion，不使用 `transition: all`。

## 实现责任边界

先找到项目真实的共享 Layout/AppShell、路由出口、侧栏状态、断点和 设计变量，再改壳层；不要在每个路由页面重复实现。

- 外层 外框 负责背景和桌面端 视口 高度。
- 侧栏负责固定定位、展开/折叠宽度、移动端抽屉和焦点行为。
- 壳层内容列 负责根据侧栏宽度设置内容 inset、桌面 gutter 以及 底部信息栏 对齐。
- 工作区表面 负责 页头、路由内容的连续背景、圆角、边框和阴影。
- 主滚动区 负责路由内容的垂直滚动，避免整页滚动导致 底部信息栏 漂移。
- 底部信息栏 负责低强调的信息，不应承担主要业务操作。

如果侧栏有展开宽度 `rail-expanded` 和折叠宽度 `rail-collapsed`，两者必须由同一个状态源驱动侧栏宽度和 壳层内容列 的左 inset。不要分别维护两套接近但不相等的 `margin-left`。

## 框架中立的实现契约

实现前先确认宿主项目真实的 Layout/AppShell、路由出口、侧栏状态、滚动策略、断点、主题 token 和组件 API。框架、渲染方式和命名由宿主项目决定；本文件只规定 DOM/布局责任，不指定 Vue、React、Svelte、CSS 方案或组件库。

结构可以用任意模板语法表达，语义关系应保持如下：

```html
<div class="app-frame">
  <aside class="navigation-rail">
    <div class="rail-brand">品牌</div>
    <nav class="rail-primary">主导航</nav>
    <div class="rail-utility">账户 / 设置 / 帮助</div>
  </aside>

  <div class="shell-column">
    <section class="workspace-surface">
      <header class="workspace-header">页面标题 / 工具栏 / 状态</header>
      <div class="workspace-panels">
        <main class="workspace-scroll-region">路由内容或主面板</main>
        <aside class="workspace-secondary-pane">可选的检查器 / 对话 / 日志</aside>
      </div>
    </section>
    <footer class="information-bar">
      <nav aria-label="产品信息">关于 / 帮助 / 隐私</nav>
      <span>版本 / 归属</span>
    </footer>
  </div>
</div>
```

责任边界保持清晰：

| 区域 | 应负责 | 不应负责 |
| --- | --- | --- |
| `app-frame` | 外层画布、桌面端视口约束、主题背景 | 页面业务、路由判断 |
| `navigation-rail` | 宽度、展开/折叠、导航分组、移动端抽屉和焦点 | 工作区内容的左边距副本 |
| `shell-column` | 根据同一 rail 状态驱动 inset、桌面 gutter、底部信息栏 对齐 | 具体页面的表格/表单 |
| `workspace-surface` | 页头、面板组的连续 surface、圆角/边框/阴影 | 每个内层区块的重复外框 |
| `workspace-scroll-region` | 路由内容的垂直滚动、横向溢出策略 | 改变壳层高度或把 底部信息栏 推出视口 |
| `information-bar` | 低强调产品信息、版本和归属 | 主要业务操作、危险操作 |

路由出口只挂载一次，通常由共享布局提供 页头 和主内容出口。多面板工作台可以有多个同级 滚动区域，但必须明确当前焦点、键盘顺序和面板之间的 resize 责任。

## 桌面壳层模式

根据页面任务选择模式，不要把所有后台都做成多栏：

| 模式 | 适合场景 | 关键约束 |
| --- | --- | --- |
| **单工作区** | 概览、列表、常规管理页 | 一个连续 工作区表面；内容列在内部控制宽度 |
| **分栏工作区** | 编辑器、监控、日志、AI 辅助工作台 | 面板同级排列，共享 面板间距；每栏独立滚动，不能互相裁切弹窗 |
| **窄列详情** | 设置、权限、成员资料、规则详情 | 采用稳定的标签—说明—值/操作行；分隔线只用于内容分组 |
| **混合工作区** | 主表格 + 详情检查器、主内容 + 辅助对话 | 主任务拥有最大空间；辅助面板可收起，状态变化不能导致主列跳动 |

分栏只在确实减少上下文切换时使用。侧栏、工作区面板和 底部信息栏 仍由同一个 shell 状态源驱动；不要为不同页面重新发明一套接近但不相等的宽度和 gutter。

## 导航、页头 和内容组合

- 侧栏从视口边缘连续到底：品牌、主导航、分组折叠、账户/设置和底部工具应在一条表面内组织；只有在产品有明确语义时才增加分组间距或弱分隔。
- active 项用项目主色的低强调 surface、文字/图标对比和清晰焦点表达；不要同时叠加高饱和背景、粗边框和强阴影。
- 图标导航折叠后必须保留可访问名称；Tooltip 只补充名称，不替代键盘路径或当前 active 状态。
- 模块介绍型 页头 可以采用“图标 + 标题 + 说明 + 可选通知/升级提示”的横向组合；紧凑管理页可以只保留标题、面包屑和操作。两者都属于 工作区 内部，不要把 页头 做成悬浮营销 Banner。
- 页签、筛选、分页、排序和选中状态在用户需要刷新、分享或返回时应进入 URL 或宿主路由状态；当前页面的主操作保持在稳定的工具栏位置。
- 页头 的下边界可以使用一条内容层级分隔线；它不能被用来补偿侧栏和工作区之间的缝隙。

## 内层页面模式

- **概览**：把同一主题的指标、趋势或安全状态收束到少量语义面板；每个面板都应有标题、单位、更新时间或下一步，不要堆装饰性指标卡。
- **设置/详情**：优先使用透明背景的 section + row 结构；标签列、说明列和值/操作列保持稳定对齐，长说明允许换行，危险操作单独分组并提供确认。
- **表格/列表**：内容列切换到宽模式；操作列稳定，数字使用等宽/表格数字，空值、加载、错误、分页和横向滚动不改变壳层边界。
- **编辑器/多面板**：面板标题、折叠、拖拽调整大小和焦点顺序要可见；把日志、检查器、对话等辅助面板做成可收起的同级面，而不是覆盖主任务的永久浮层。
- **空状态/错误状态**：在当前内容列内给出原因和下一步；不要用一个巨大的居中 Card 把整个工作区重新包起来。

## 底部信息栏 / 底部信息栏

只有产品确实需要这些信息时才显示 底部信息栏。它应当紧凑、低对比度、与工作区边缘对齐，不要抢占页面主要任务：

- 左侧可以放关于、协议、安全、隐私、更新日志、帮助和语言等信息。
- 右侧可以放版权、版本、构建时间或产品归属。
- 宽屏保持在同一基线；窄屏根据空间改为换行或上下堆叠，不能产生横向滚动。
- 分隔符只用于有意义的链接之间，并且遵循项目已有写法；不要用贯穿整行的边框代替间距。
- 如果文字暂时不是可点击链接，应明确它是说明文字，不要伪装成可交互控件。

## 响应式模式

### 桌面端

- 侧栏常驻，外层 外框 锁定视口高度。
- 工作区显示桌面 gutter 和一套圆角/边框处理。
- 底部信息栏 位于工作区之外，若有真实信息则显示。
- 路由内容在工作区的 滚动区域 内滚动，侧栏和 底部信息栏 保持稳定。
- 单工作区页面把内容列控制在适合阅读的宽度；宽表格或多面板页面才使用可解释的全宽区域。
- 多面板页面保持同级面板的共同顶/底边界；辅助面板可折叠，但不应覆盖主任务或制造第二套外框。

### 平板和窄桌面

- 按项目现有行为选择侧栏折叠、图标 rail 或抽屉化；不要引入第二个漂浮侧栏卡片。
- 如果工作区仍保留外层 gutter，优先减少内容列内边距而不是压缩文字和控件命中区。
- 多面板按任务优先级收起次要面板或改为可切换视图；不要把三个窄栏硬塞在同一行。
- 保持内容与侧栏的 inset 关系，底部信息栏 链接允许换行但不溢出。

### 移动端

- 工作区填满视口，移除会挤压内容的桌面 gutter 和圆角。
- 侧栏改为带遮罩的抽屉，触发按钮、Escape、焦点返回都要可用。
- 底部信息栏 如果会干扰主要任务，可以隐藏或堆叠，但不能让它被裁切在视口下方。
- 不要同时给 外框、页面、抽屉设置互相冲突的 `overflow: hidden`。
