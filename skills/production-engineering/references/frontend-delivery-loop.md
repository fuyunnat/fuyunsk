# 前端交付闭环

新模板按 `frontend-stack.md` 先完成视觉阶段：外观、布局、组件及可看的本地交互，再按授权安排业务接入。视觉阶段说明示例数据、未接功能和阶段未测项，不被整站功能盘点或真实CRUD验收拖住；前端预览不等于业务通过。普通已有页面小改继续保留已接的接口和业务，不要求解绑或改成模拟；既有功能仍按影响真实回归。

用于前端、后台和公开页面从代码改完走到可交付的任务。页面或样式修改默认加载；普通组件小改、后端接口和纯只读可不加载。它补充现有前端、Git、SEO 和项目边界规则，不替代也不扩大授权。

## 先固定输入与工具能力

- 设计上下文：优先读取用户提供的 Figma 文件/链接、截图、设计 token 和交互说明；没有 Figma 时用源码、现有页面、截图和一页 Design Brief 代替。不能凭现代、好看自行补齐品牌、布局或业务含义。
- 语义代码理解：有 Serena、语言服务器或其他符号级工具时，先按符号、调用方、引用和类型关系定位；没有就用项目现有索引、AST、rg、测试和构建入口。工具不可用时降级，不把工具名称写成已执行证据。
- 真实页面验收：有 Browser/Chrome 或可交互预览时必须打开真实路由；没有浏览器、账号、服务或稳定数据时，明确标记视觉验收未完成，不能用 build、单张截图或代码自评替代。
- 协作与预览：有 GitHub 能力时用分支、差异、PR 和 CI；有 Vercel/Sites 或项目现有预览通道时生成预览。没有连接或授权时提供可复现的本地检查结果，不声称已 Review、部署或上线。

工具状态只记录三种：已执行并有证据、可用但本次未用、不可用/被阻塞。安装 Serena、浏览器、Vercel 或业务依赖不属于本专项默认授权。

## 先开页面，边改边看

前端任务默认尽早交付**持续可访问的开发预览**，让用户边改边看、随时反馈；不要等全部功能、完整测试或最终汇报后才给地址。

- 先核对项目已有启动方式和正在运行的服务。健康且能加载当前改动就复用，尽量保持同一地址和受影响页面路径；已有热更新就使用，没有则说明需要刷新或必要的受控重启，不假称自动更新。不要每次小改都重启服务、换端口或另建预览平台。
- 尽早在真实浏览器打开受影响页面，确认实际可达、确实是当前改动的版本，再把可打开的网址和页面入口发给用户。AI看过截图不等于用户能打开；运行环境在别处时说明真实访问方式，不把远程机器的localhost写成用户电脑地址，不擅自部署公网或安装转发工具。
- 按已授权的项目现有配置启动。用户明确指定 `.env` 等配置时遵从，不静默换成SQLite、mock、演示数据或另一套数据库；需要隔离测试时单列用途，说明用户预览与自动测试各自的数据来源，不能混称。不要显示连接串、密码、令牌或用户隐私。
- 启动前只核对实际会执行的隐式迁移、自动建表、后台任务和外部写入。连接现有数据库不等于授权改结构、清库、修改全站设置、扣款或发信；复用已有安全启动选项，不能为展示新模板悄悄切换全站模板。确实无法安全启动时说清具体卡点，继续独立工作，不擅换数据来源，也不重复索要已给过的授权。
- 页面可用后保持预览运行，用户可随时访问；修改生效时简短说明改了哪里、是否需要刷新。记录真实地址及必要运行会话，交付前复查仍可访问；不因一个测试批次结束关闭用户正在看的服务。现有项目尚不能运行或缺账号/权限时，先说明限制，完成最小必要修复后立即补地址，不为预览无限修复旁支问题。
- 普通小改只复用已有预览并检查受影响页面，不新增整套QA、CI、部署或守护服务。边改边看不等于验收通过；仍按影响做真实操作测试，明确哪些页面还没好、没测或缺条件。

## 标准闭环

1. 基线：读取目标页面、布局、样式、资源、路由、接口和状态；记录桌面/移动视口、账号、固定数据和当前截图/URL。严格原样迁移沿用旧版基线，新设计先形成短 Design Brief。
2. 语义地图：列出入口组件、关键符号、数据流、路由守卫和影响调用方。优先复用已有组件；共享层修改先查主要使用方。Serena 只提高定位精度，不替代项目测试和行为回归。
3. 最小实现：按当前框架和 frontend-stack.md 写代码；先完成能暴露问题的代表页/代表状态，再扩散到相邻页面。代表页通过布局、响应式和关键交互验收前，不批量复制同一套页面。保持原业务 API、权限、数据、副作用和响应式要求；不因视觉优化顺手换栈。
4. 浏览器循环：复用前述持续预览和项目既有开发命令，在真实浏览器打开受影响路由，检查正常、loading、empty、error、权限、弹窗/表单、键盘焦点、长文本、宽屏/笔记本/移动视口；同时判断布局是否合理、组件是否协调、颜色/字体/图标是否沿用项目规则。页面有输入框、表单、筛选、上传或按钮时，用安全测试值实际填写和操作，检查校验、加载、成功、失败和空状态；真实提交、支付、发信或生产数据改用隔离数据，缺条件就列为未验证。发现问题就回到实现再测；浏览器不可用则逐项列未验证项。
5. 证据包：保存必要的 URL、视口、截图/录屏、控制台或网络错误、测试命令与结果；敏感账号、Cookie、Token 和用户数据不得写入日志、PR 或截图。截图不能替代交互测试，单一正常态不能代表页面通过。
6. 交付：提交前运行项目测试、lint、typecheck、build 及必要的页面检查；按 git-team-delivery.md 创建可审查逻辑提交和分支。PR 描述写改变项、保留项、验证证据、未验证项和回滚点；Review 意见先对照源码和测试再改。
7. 预览门禁：有 Vercel/Sites 或既有预览通道时，仅在授权范围内发布预览并记录 URL、版本/commit 和状态；预览失败或没权限就停在可复现本地证据，不把已推送写成已部署。生产发布、合并主线、改域名和改环境变量仍需单独授权。

## 完成判定

前端交付不是代码能编译。设计输入及缺口、影响范围、浏览器/视口/状态/可访问性、Git交付、预览版本、风险与回滚等技术证据记入清单或详细报告；给用户按 `verification-report.md` 的五项用大白话说实际页面能不能用、亲手点填了什么、哪里还没好。任何一项没有证据就写未验证，不允许用其他项目截图、旧 CI、模型自述或计划清单冒充。
