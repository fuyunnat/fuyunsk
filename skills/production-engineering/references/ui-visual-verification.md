# UI视觉精修与视觉回归

本专项只在用户要求“页面别扭、间距/对齐/排版、换屏幕跑版、溢出、响应式错位、对照参考图、像素还原、视觉回归”时加载。普通前端功能、严格原样迁移和单纯业务 Bug 不自动加载；已有业务逻辑、接口、权限、数据、交互和原貌边界优先。

## 非设计师交付的视觉闭环

用户把新页面或视觉改版交给 AI 设计时，先由 AI 做主方向与代表页，再用实际截图检查宽屏/手机的排版、对齐、信息层级、长文案与关键状态；集中修复最重要的缺陷，再对受影响视口复查。没有参考图时以现有项目和任务场景为依据做经验审查，不伪称像素还原；保留截图或可核查的测量结果，明确已验证与未验证部分。

若后端启动会隐式迁移或连接现有数据库，使用隔离的前端 mock 或独立组件预览，不启动连接现有业务库的服务。不能因为真实后端不宜启动就放弃前端静态检查与可隔离的视觉验证；隔离环境无法构建时报告视觉验收未完成。

## 三层职责

- **精修诊断**：把问题先归类为布局/间距、对齐、字体与行高、颜色对比、层级、密度、状态或动效，再按影响优先修复。检查随机字体、随机颜色/圆角、重阴影、Card 套 Card、无意义动效和模板拼装感，但只有违反产品或设计证据时才判错。新页面先记录最小 Design Brief；长期稳定的视觉契约才写入 `DESIGN.md`。
- **多视口完整性**：固定一组代表视口（至少宽屏、普通桌面、平板、手机；按项目实际补充），保存基线、当前截图和差异/缺陷清单。先扫横向溢出、裁切、遮挡、错位、换行、断点重排和滚动异常；每轮只修最小 CSS/布局原因，再在同一视口矩阵复测。字体、数据、时区、动画和网络状态要稳定；不因截图差异盲改业务。
- **参考图还原**：有 Figma/设计稿/参考截图时，先建覆盖表，再逐项绑定“参考节点/区域 → 页面选择器或组件 → 期望属性 → 实测属性 → 证据 → 状态”。期望值来自设计源，不从现有 DOM 或截图猜测；外到内按容器、布局、间距、字体、颜色、状态逐层推进，外层未过不扩散到内层。重要交互状态、长文本和错误/空状态也要列入覆盖范围。

## 执行闭环

1. 读取真实页面、入口、样式、组件、设计源和已有视觉规则，写清改变项、保留项、参考依据和代表视口；没有设计源就标记“经验审查”，不能伪称像素级还原。
2. 先做静态/确定性检查，再做浏览器真实检查：计算溢出（`scrollWidth > clientWidth`）、元素矩形、computed styles、字体加载和关键状态；截图/像素差用于发现渲染差异，不把单张截图或模型主观评价当唯一通过条件。
3. 对每个缺陷记录最小证据：视口、元素/选择器、期望或不变量、实测值、根因假设、修改文件和影响面。每次修复只改变一个可解释原因，复测同一断点后再进入下一项。
4. 代表页通过后再扩散到相似页面；组件级问题先在组件/故事页验证，再做整页回归。多代理或多阶段时按“实现 → 视觉复核 → 代码复核”顺序，不并行修改同一页面。
5. 交付报告区分：静态检查通过、浏览器已验证、参考图已逐项核对、无法执行/工具缺失、仍待用户确认。没有 Browser/Playwright/Figma 或稳定基线时，明确降级，不把源码存在写成视觉验收完成。

## 缺陷分类与停止条件

优先修复会改变阅读顺序或交互的层级/布局问题，其次是溢出、对齐、字体度量和密度，再处理颜色、圆角、阴影和微动效。若改动会影响接口、权限、业务状态、数据格式或共享组件多个使用方，停下说明 blast radius 和回滚点，按原有高风险规则确认。

完成最低条件：代表视口无明确溢出/遮挡；关键组件在正常、loading、empty、error、disabled 和主要交互状态可解释；参考图覆盖表没有未处理的关键项；每个视觉修复都有测量或设计源证据。工具不可用、基线不稳定或设计源缺失时只能报告“视觉验收未完成”。

## 工具与来源边界

优先复用项目已有 Browser/Playwright、Figma、截图和测试能力；不为一次审查安装整套外部 Skill 或引入未经授权的依赖。可借鉴公开方法，但用本仓库自己的步骤和措辞：

- [Impeccable](https://github.com/pbakaus/impeccable)：Apache-2.0；参考其产品上下文/视觉方向分离、确定性 UI 检查、分类式 critique/polish 和浏览器内迭代。
- [VLMKit](https://github.com/mizchi/vlmkit)：MIT；参考其多视口 integrity、基线→差异→复测、机器可读缺陷和 CSS fix loop。
- [Pixel Twin](https://github.com/aochengyu/pixel-twin)：仓库当前未声明明确许可证；只吸收覆盖表、computed styles 优先、外到内和逐项证据方法，不复制其代码、脚本或原文。

这些方法不能改变本技能的原文优先、行为锁、项目写入边界、Git 授权和“未执行不声称完成”要求。
