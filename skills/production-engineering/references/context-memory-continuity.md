# 上下文续航与任务状态

执行条件与内容以原文 `rules/02-06.md` 为准。完整通道、长任务、多文件、多阶段、提交推送部署和恢复旧任务使用检查点；快速单步任务可以跳过。**新开对话本身不触发恢复命令。**

## 用户可见的根目录清单

每次实现任务（包括小改）的待办、进行中和完成勾选，统一记录在当前目标项目根目录 `工作流程.md`（不是 Codex/技能目录）；不能只藏在下面的旧快照位置。逐项完成并验证后即时打勾，未测试保留待验证；新增事项追加，继续任务先读当前区块，保留历史和用户内容。按 `workflow-checklist.md` 与既有快照/迁移台账关联，不复制多份独立待办。只读不写，除非用户明确单独授权清单写入。

以下位置只适用于仍需完整任务状态助手的底层快照和证据，不代替根目录清单；小改不用为此启动助手。清单中记录旧快照/台账的实际路径，旧快照的目标、来源与下一步引用清单任务编号。

## 存放与恢复

优先使用已有等价状态位置或已忽略的 `work/task-state.md`；否则使用项目外的 `$CODEX_HOME/task-states/`，不得只为隐藏代理记录修改项目 `.gitignore`。状态不混入业务提交，不记录密钥、个人数据或完整敏感日志。

需要恢复时，确认准确项目再运行：

```bash
node <技能目录>/scripts/task-state.js resume --repo <项目或工作区> --json
```

助手先查精确项目，再只查本地索引登记的下级项目，不遍历磁盘。多个候选不得盲选。完成状态只作历史；核对路径、分支、HEAD、差异、用户改动、禁止项和最新目标，真实状态优先。

## 必要内容与更新频率

保留目标、验收、模式和通道、入口与技术栈、真实运行及验证命令、决策与原因、已改和计划文件、禁改范围、执行结果、分支稳定点、用户改动、阻塞、下一步、远端状态及回滚。状态是断点检查点，不是开发日记；开始、实现结束、验证、远端交付、阻塞和完成时更新，不按每个细节反复重写。

原始证据留在安全位置，状态只记摘要和证据路径。内置记忆只能提供线索，不能替代当前文件、Git 与运行结果。不得默认安装或调用外部记忆服务。

## 保留源码依据与已确认边界

需要续航的任务，把参考源码实际路径/版本、允许改变项、必须保留项、关键文件证据、已确认回答和未解决歧义放进已有目标、验收、决策、来源、禁改范围和阻塞字段。不要复制整套源码或另建重复台账；不因小改强制创建状态。

恢复时先核对这些约束与真实文件；“仅换实现、保留原貌”不能被聊天压缩成“重写页面”。已有明确答案不重复询问，不回退到技能默认栈；源版本变化或证据丢失时只补查相关部分，仍有关键冲突才询问。只读任务保持只读，状态更新仍遵守原有授权与阶段边界。

## 助手命令

```bash
node <技能目录>/scripts/task-state.js init --repo <项目> --goal "任务目标" --lane "完整通道"
node <技能目录>/scripts/task-state.js implementation-complete --repo <项目>
node <技能目录>/scripts/task-state.js run --repo <项目> -- <验证程序> <参数>
node <技能目录>/scripts/task-state.js check --repo <项目>
node <技能目录>/scripts/task-state.js finalize --repo <项目>
```

`init` 拒绝覆盖未完成任务；已有完成记录先归档。`update` 不得直接设置完成或通过；`run` 无 shell 执行验证并绑定当前文件指纹，包括未跟踪内容。后来改动会使旧验证失效。只有实现完成、验证通过且指纹仍相同才能 `finalize`。一次命令成功不代表全部适用验证完成，代理必须确认所需检查都已执行。

非 Git 项目不能自动证明版本指纹，改用备份与明确文件证据，不能声称自动完成证明。保留原有命令、JSON 字段和状态枚举兼容；人可读标题、帮助和错误说明使用中文。

## 状态规则

实现完成但未测试仍在进行中；验证失败、不可执行或后来再次修改，必须保留未完成状态与原因。完成说明和实际交付一致，不能出现“完成但待测试”。只读任务不得因续航记录而修改项目或外部业务状态。

## 整项目迁移的额外检查

仅整项目重写、跨语言或全量架构迁移追加 `project-migration.md`。原有任务快照记录台账路径与锁定值，不把全部功能复制进快照。初始化时加 `--migration <台账路径>`；已存在的未完成任务使用 `attach-migration` 登记，不能覆盖已有绑定。

绑定后 `check` 和 `finalize` 会核对全部旧功能去向与独立验收凭据；普通测试命令退出成功不能绕过缺项、旧证据或未演练恢复。继续开发先核对台账、基线、当前模块和真实差异；压缩后不凭聊天摘要猜进度。未绑定的旧任务仍沿用原机制，不会自动获得迁移覆盖检查。

## 聊天项目绑定不能被工具路径覆盖

根目录可见清单以当前聊天关联源文件夹的 `PROJECT_ROOT/工作流程.md` 为准，恢复先核对项目身份和实际路径。旧状态助手的注册表、Git 根定位和技能 `__dirname` 都不是这份清单的路径来源；其旧状态协议保持兼容，但不得借用其项目外存储来替代用户要求的可见清单。切到另一聊天项目时重新核对，不串用任务或勾选状态；同一目标中发现的漏项持续追加，不等待用户预先审批整表。
