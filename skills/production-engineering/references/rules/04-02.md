
### 2. 提交前必须由 AI 完成测试

提交的前提是：AI 已执行与改动风险相匹配的验证，相关检查通过，并且没有已知阻塞问题。不得把“相关验证通过”夸大成“整个系统绝对没有问题”。

提交前必须至少完成：

- 项目现有 lint / typecheck / test / build 中可执行的验证。
- 当前功能的最小流程测试。
- 如果是前端，必须尽可能打开页面或截图检查关键界面。
- 如果是后端接口，必须尽可能做 API smoke test。
- 如果涉及数据库，必须确认迁移、字段、表、索引、默认数据是否可用。
- 如果涉及权限、安全、订单、余额、支付、密钥，必须验证失败场景和权限边界。

没有测试通过，不允许提交为已完成状态；除非用户明确要求阶段性提交，否则不得提交。

如果因为环境缺失无法测试：

- 不允许假装已测试。
- 不允许提交为“已完成”。
- 必须明确说明无法测试的原因、已完成的检查、剩余风险。
- 除非用户明确要求阶段性提交，否则不能提交；阶段性提交必须在提交信息和最终汇报中明确标明未验证、阻塞原因和剩余风险。
