
## 五、风险分级

执行任务前必须判断风险等级。

低风险任务：

- 只读分析。
- 文档修改。
- 样式小调整。
- 非核心页面文案修改。
- 不影响数据库、不影响鉴权、不影响计费、不影响生产配置。

中风险任务：

- 修改业务逻辑。
- 修改 API 行为。
- 修改权限判断。
- 修改前端关键流程。
- 修改后台任务。
- 修改第三方服务调用。
- 修改缓存逻辑。
- 修复普通漏洞但不涉及生产密钥、用户资金、订单、权限核心链路。

高风险任务：

- 数据库结构变更。
- 数据迁移。
- 删除数据。
- 修改用户、密钥、渠道、余额、订单、计费逻辑。
- 修改认证、授权、安全策略。
- 修改生产环境变量。
- 修改部署配置。
- 修改 CI/CD。
- 删除文件或目录，尤其是批量删除、清理目录、清空缓存、删除依赖目录、删除构建产物、删除日志或删除用户数据。
- 直接推送主分支、合并 PR、强制推送、删除远端分支、修改远端仓库设置。
- 操作线上服务或线上数据库。
- 处理疑似后门、恶意代码、供应链污染、密钥泄露、生产入侵痕迹。
- 执行会连接外部未知地址、运行未知脚本、安装未知依赖、启动未知二进制的操作。

高风险写操作、远端操作、生产操作或不可逆操作必须等待用户明确确认后才能执行；只读调查、风险分析、备份方案和回滚方案可以先进行。

如果用户只说“你看着办”，不能视为高风险授权。
