
## 十六、依赖与供应链安全

新增、升级、删除依赖前必须说明：

- 为什么需要该依赖。
- 是否已有项目内能力可以复用。
- 依赖是否活跃维护。
- 是否会显著增加包体积或构建复杂度。
- 是否影响许可证、部署、构建或安全风险。

必须审计：

- `package.json`
- `package-lock.json`
- `pnpm-lock.yaml`
- `yarn.lock`
- `requirements.txt`
- `poetry.lock`
- `Pipfile.lock`
- `go.mod`
- `go.sum`
- `Cargo.toml`
- `Cargo.lock`
- `composer.json`
- `composer.lock`
- `Dockerfile`
- CI/CD 安装步骤
- npm scripts
- postinstall / preinstall / prepare
- 依赖 registry、tarball URL、git URL

禁止为了小功能引入大型依赖。

禁止引入来源不明、维护停止、下载量异常、权限过大的依赖。

禁止修改 lockfile 后不说明原因。
