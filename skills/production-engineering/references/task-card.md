# 任务卡

任务卡是实施前的最小判断，不是第二套待办，也不替代用户授权。

## 什么时候用

- 只问不改、解释、翻译和纯审计：不建任务卡。
- 快速小改：在当前对话或工作笔记里保留一张短卡，不创建 `工作流程.md`，也不启动进度面板。
- 复杂、跨阶段、跨模块、需要续作或用户明确要求进度：在第一次业务写入前，把卡片合并到目标项目根目录的 `工作流程.md`。

## 最小字段

```markdown
任务级别：快速小改 / 复杂任务 / 需要续作
目标：要改变的可观察结果
证据/基线：现象、源码位置、现有行为或待查事实
必须保持：接口、数据、权限、旧行为和其他明确边界
允许范围：本次可以改的文件、模块或外部动作
方案：选择的最小方案；必要时列一个被放弃的更大方案
风险与回退：可能失败的地方和恢复方式
验收：完成的具体证据、测试或人工检查
真实测试条件：项目、服务、账号、数据、浏览器、依赖和权限
未验证/缺口：还没测什么、原因、需要用户提供什么以及提供后怎么测
当前动作：下一步要做什么
```

## 使用规则

1. 字段缺证据就写“待查”，不能用猜测填满。
2. 任务卡只记录当前目标和边界；新增需求先判断是否升级范围，再决定是否追加到清单。
3. 方案、风险或证据变化时先更新任务卡，再继续写入；不要在失败补丁上叠加猜测。
4. 快速小改升级后，把已有短卡迁移到 `工作流程.md`，保留原目标和已确认事实。
5. 任务卡完成不等于验收完成；只有验收证据成立后，清单事项才能标记已完成。

## 小白默认

- 用户只需说想要的结果，不需要填写任务级别、方案或命令；AI 从源码、运行结果和已有记录里补齐任务卡。
- 任务卡内部可以保留技术细节，但对用户只报告目标、进展、结果和下一步，不要求用户做技术选择。
- 交付先用简单大白话说清改了什么、现在能做什么、还差什么；专业术语和命令只在有助于核对时补充。
- 写入任务收尾必须报告已做、没做、怎么测、还没测什么、缺什么五项；没有内容也明确写“没有”。
- 只有查证后仍会导致不同结果的歧义才提问，并用人话给出 2–3 个结果选项和推荐。
