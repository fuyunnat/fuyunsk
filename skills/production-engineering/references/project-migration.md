# 整项目迁移与防遗漏

仅用于整项目重写、跨开发语言迁移或全量架构迁移。普通解释、局部重构、单次数据库迁移、页面小改不加载本流程。此流程补足原文第二章续航、第六七章边界、第十章兼容、第十二十三章迁移回滚及第二十章验收，不改原稿、不扩大授权。

## 一、先限定迁移，不把“换语言”变成重做业务

先固定旧系统提交或内容哈希、目标语言与运行环境、迁移范围、受保护行为、授权范围、验收标准和旧版回退点。接口、数据库、UI、业务规则、部署方式分别判断，不能顺手全部更换。已授权的新页面选型仍为 shadcn/ui + Tailwind CSS；只迁后端不因此重写已有页面。

只读规划只读取并报告证据，不创建台账、任务状态或业务文件。开始实现前才在已授权范围保存迁移材料；未知脚本先审查。迁移不等于授权生产切换、真实支付、短信、邮件或永久删除旧实现。

用户已给源码时，必须读取它的相关实现、样式、资源与调用关系；不把目录清单当完整理解，也不先索要已提供材料。迁移台账中的行为与验收来源应指向原版本和具体代码，记录明确的改变项、保留项及待确认事项。换语言/框架不等于重做设计或业务；当前明确目标优先于默认选型，HTML 换 Vue 仅是这个通用原则的一例，不新增独立专用流程。

要求保留 UI 的迁移逐页记录原版视觉与交互基线，使用前端质量说明中的新旧对照；只读源码或编译通过不能替代视觉一致性证据。仅做局部框架适配时不机械启用整项目迁移台账。源码已明确的直接执行；关键歧义查证后仍无法消除才暂停相关修改并问清，不能自行用新样式填空。

## 二、建立旧功能对照，不按文件机械翻译

交叉盘点真实路由、页面菜单、公开与内部 API、鉴权与角色权限、初始化、迁移脚本、定时任务、队列消费者、Webhook、导入导出、配置开关、监控、启动及部署入口。结合调用方、现有测试与允许读取的运行证据复核，不只读 README。找不到证据的标为未知；不适用的写明依据。

每个旧能力分配稳定编号，记录旧位置、外部可观察行为、调用方、数据与副作用、依赖功能、必需用例、新位置和当前状态。同一能力拆分为多个新模块时保留一对多关系；发现新入口继续补盘点，不因为“看起来差不多”省略。

将复核后的旧功能与验收清单固定为 `inventory.json`，保存 SHA-256；可参考技能 `templates/migration-inventory.example.json`。这是本次迁移的分母，不是可随进度缩小的待办列表。来源清单仍可能漏项，必须交叉审查，脚本不会理解并自动发现全部业务能力。

基线至少含：旧版本、原语言、目标语言、范围、盘点来源与审阅记录；每项的 `id`、`name`、`oldLocations`、`behavior`、`dependsOn` 和 `requiredChecks`。额外全局验收固定 `full-regression`、`resume-drill`、`rollback-drill`；编号可以是技术英文，说明必须中文。

## 三、台账和断点是两层记录

使用 `templates/migration-ledger.example.json` 创建 `ledger.json`，沿用项目已有等价材料，不创建多套真相来源。台账以基线哈希绑定旧清单，逐项记录新实现和证据。`targetFiles` 列出参与迁移的目标源码、共享依赖、本次测试程序、关键构建配置与锁文件，文件相对目标项目根目录；不把台账、交接记录和执行凭据列入，避免记录自身形成循环指纹。

目标文件范围必须人工交叉审查：未列入文件的变化不能由这个局部指纹自动发现；最终仍须完整项目差异检查与适用回归。不得为绕过失败而移出源码或测试。清单不是自动依赖图，不用它代替项目测试。

材料放在明确的项目文档位置或已批准的外部位置；敏感数据、凭证、完整日志不入库。跨电脑、多人接手时明确哪些无敏感材料随项目版本管理；项目外台账和证据须另行安全同步，不能假设 Git 会带走。快照只记台账路径、固定基线、当前模块、决定、禁改范围、下一步和阻塞，不复制全部条目。

初始化任务时绑定（替换实际路径，不直接执行占位符）：

```bash
node <技能目录>/scripts/task-state.js init --repo <目标项目> --goal "整项目跨语言迁移" --lane 完整通道 --migration <台账绝对路径>
```

已有未完成任务先恢复，再用 `attach-migration --repo <目标项目> --migration <台账路径>` 追加绑定，不覆盖任务。绑定后 `update` 不能移除或替换基线；盘点有新发现时保存新基线和新台账，使用 `extend-migration --repo <项目> --migration <新台账> --reason "发现遗漏入口并追加盘点"`。它只允许追加，不允许删除或改写旧功能、旧用例、来源版本和目标边界；记录旧绑定并使旧验证失效。改变既有验收标准须单独确认和设计变更流程，不能借扩充弱化旧要求。

## 四、每次迁一个能验收的业务闭环

先新旧并存，按依赖顺序迁移一个模块，跑同一组行为用例对照，再进入下一个。保留旧实现直到对应替代、数据兼容和回退均验证；旧代码清理与生产切换另行确认。

对照请求、响应、错误、权限、默认值、空值与缺省值、金额精度、时区、排序分页、字符编码、并发、事务、超时重试、幂等及副作用。只比较适用字段，动态值的归一化需要明确规则和审查，不能把差异全忽略。历史 Bug 或安全缺陷列为经批准改变的行为，不盲目复制，也不静默修成另一套业务。

测试使用隔离环境、合成数据和替代外部服务。新旧各发一次请求不得造成真实重复扣款、短信、邮件或回调。实际测试程序必须对新旧行为作独立断言，编译成功、命令 `true` 或 `process.exit(0)` 不构成业务验收。

台账状态为：未开始、进行中、已实现、已验证、保留旧实现、确认废弃。已实现不等于已验证；保留旧实现只能报告阶段性共存，不得称全量重写完成；确认废弃必须记录原因、批准来源及可核对的授权证据。不得直接删行来获得完成状态。

## 五、逐项执行凭据，不只填“通过”

`migration-check.js check` 是只读检查；不会执行台账里的命令，不会自动生成或安装依赖。`run` 仅在执行者确认测试环境和副作用后，显式运行已审查的测试程序，使用独立进程、有限超时、不经 shell；默认两分钟，最高十分钟。每个结果文件必须新建，不覆盖历史失败。

```bash
node <技能目录>/scripts/migration-check.js run --repo <目标项目> --manifest <台账> --case <用例编号> --output evidence/<新的结果名>.json -- <实际测试程序> <参数>
node <技能目录>/scripts/migration-check.js check --repo <目标项目> --manifest <台账> --json
```

提前建立无敏感信息的证据目录。`run` 输出可登记到台账 `checks` 的相对路径和 SHA-256；保存旧版本、盘点锁、目标文件指纹、实际命令、退出码和输出摘要哈希，不保存原始日志。失败、超时或验证期间目标变化都不能成为通过凭据。输出原文不回显，详细失败在测试项目自己的安全诊断路径查看。

所有必需用例均要有对应的执行凭据。一个真实测试套件已覆盖多项时可用 `--case 编号1,编号2` 一次运行，共享带对应编号的凭据，不重复跑相同命令；不得把未被套件断言覆盖的编号填进去。目标源码、测试、配置或文件列表变化后旧凭据失效；最终冻结差异后成批执行全部适用用例，减少来回。基线来源的真实性、命令断言是否充分、人工批准是否合法仍需要审查；本地文件可编辑，不是密码学认证或不可绕过的平台沙箱。

绑定迁移的 `task-state.js check` / `finalize` 会追加此检查：缺功能、重复编号、依赖未验、只有“已实现”、仍保留旧实现、证据缺失/篡改/过期、全局验收缺项、交接文档缺失或还有阻塞，都会拦截迁移完成。单个普通命令成功不能替代它。未绑定的旧任务不会凭空获得此机制。非 Git 项目仍需人工备份与文件证据，原状态助手不提供自动完成证明。

## 六、恢复演练与交接

阶段结束、阻塞、压缩前或切换模型前保存短检查点；真正中断且来不及记录时，先核对真实 Git 差异再恢复，不能假装最后快照必然最新。清单和证据丢失就恢复备份；不能凭聊天摘要重造“全部通过”。

恢复只读当前模块及其依赖的详细记录，不每轮扫描全项目。实际文件、最新用户要求与过期快照冲突时，以当前事实为准并使受影响证据失效。多人并行必须分配模块和独立工作区，不同时改同一台账；汇总后重新验证组合结果。

至少做一次无历史聊天的恢复演练：新会话只依靠安全的项目材料复述固定旧版本、目标、已验证与待办、当前模块、下一步、禁改范围和回退点；先只读核对再允许继续。`handoff` 指向已哈希的交接文档；`resume-drill` 用例核对演练报告的事实，不因助手自称“记得”而通过。无法启动独立会话时记录未验证，不伪造演练成功。

## 七、完成与切换分别判断

全量迁移完成需要旧清单每项已验证或有真实批准的废弃，依赖与所有必需用例通过，全量回归、恢复演练、回滚演练均有证据，交接材料可读，没有阻塞。已验证数量不是代码行数；报告分别列迁移、废弃、保留旧实现、待验和阻塞数量。

通过清单检查只说明已登记范围的记录和执行凭据一致，不等于绝无遗漏、模型绝不遗忘或已经上线。先按原文完成代码与数据、配置、运行环境的分级回退，再按单独授权灰度切换与观察；没有生产操作就报告“未切换生产”。

## 八、不拖慢普通任务

仅识别到整项目迁移后加载本专项。与当前领域批量读取：`read-rules.js --stage 实现 --topic 整项目迁移,后端`；只读计划用 `--stage 只读`，不创建台账。普通按钮修改、通用问答和局部重构不读取本专项、不运行迁移检查。

盘点一次，增量维护；同阶段规则取并集。文件指纹与逐项验收只在显式验证、交付或恢复时执行，不常驻监控、不每条消息全量重跑。必要验证成本不能以“提速”省掉。

## 根目录展示逐项进度

项目根目录 `工作流程.md` 是迁移的可见工作入口，旧功能编号可直接用于清单，当前模块做完并通过对应验收才打勾；新发现事项追加，未验标待验证、失败标阻塞。根目录清单链接本流程固定台账和证据，不复制一套不同的功能分母。恢复先读根目录当前任务区块再读当前模块记录；清单全勾不代表迁移门禁自动通过，原 `check` / `finalize` 逐项凭据检查不变。
